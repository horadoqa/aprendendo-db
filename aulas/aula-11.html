O que é uma View?

Uma View é uma consulta SQL armazenada no banco de dados que pode ser utilizada posteriormente como se fosse uma tabela virtual.

Em termos simples:

Uma View permite dar um nome a uma consulta que você pretende reutilizar.

Imagine que frequentemente precisamos consultar clientes ativos.

Poderíamos escrever: 

SELECT

    id,
    nome,
    email

FROM clientes

WHERE ativo = true;

Em vez de repetir essa consulta várias vezes, podemos criar uma View.

Criando uma View 

CREATE VIEW clientes_ativos AS

SELECT

    id,
    nome,
    email

FROM clientes

WHERE ativo = true;

Depois podemos consultar a View: 

SELECT *

FROM clientes_ativos;

A aplicação pode consultar clientes_ativos sem precisar repetir toda a lógica da consulta original.

View com JOIN

Views também são úteis para esconder consultas mais complexas. 

CREATE VIEW resumo_pedidos AS

SELECT

    p.id AS pedido_id,

    c.nome AS cliente,

    p.total,

    p.data_pedido

FROM pedidos p

JOIN clientes c

    ON c.id = p.cliente_id;

Depois: 

SELECT *

FROM resumo_pedidos

ORDER BY total DESC;

Dessa forma, a consulta complexa fica encapsulada dentro da View.

Quando utilizar Views?

♻️

Reutilização

Evitar repetir consultas complexas.

🧹

Simplicidade

Esconder detalhes de consultas complexas.

🔐

Segurança

Expor somente determinadas colunas ou registros, conforme a configuração de permissões.

📊

Relatórios

Criar consultas padronizadas para análises.

O que é uma Function?

Uma Function é uma função armazenada no banco de dados que pode receber parâmetros, executar uma lógica e retornar um resultado.

Uma forma de pensar:

Uma Function é parecida com uma função existente em uma linguagem de programação.

Ela recebe uma entrada, executa uma lógica e produz uma saída.

Exemplo de Function

A sintaxe pode variar entre os SGBDs. O exemplo abaixo utiliza PostgreSQL. 

CREATE FUNCTION calcular_desconto(
    valor NUMERIC
)
RETURNS NUMERIC
LANGUAGE SQL
AS $$

    SELECT valor * 0.90;

$$;

Agora podemos utilizar a função: 

SELECT

    calcular_desconto(100);

O resultado será: 

90.00

Function consultando dados

Uma Function também pode utilizar dados armazenados no banco, dependendo do SGBD e da linguagem utilizada.

Por exemplo, podemos criar uma função que retorna a quantidade de pedidos de um cliente. 

CREATE FUNCTION quantidade_pedidos(
    cliente INTEGER
)
RETURNS INTEGER
LANGUAGE SQL
AS $$

    SELECT COUNT(*)

    FROM pedidos

    WHERE cliente_id = cliente;

$$;

Utilização: 

SELECT

    quantidade_pedidos(10);

O que é uma Stored Procedure?

Uma Stored Procedure é um conjunto de instruções armazenado no banco de dados que pode ser executado através de um comando.

Procedures são úteis quando precisamos encapsular uma sequência de operações.

Diferença conceitual:

Uma Function normalmente é utilizada para produzir um resultado.

Uma Procedure é frequentemente utilizada para executar uma sequência de operações.

A forma exata de trabalhar com cada uma depende do SGBD.

Exemplo de Procedure

No PostgreSQL podemos criar uma procedure utilizando CREATE PROCEDURE. 

CREATE PROCEDURE atualizar_status_pedido(
    pedido INTEGER,
    novo_status TEXT
)
LANGUAGE SQL
AS $$

    UPDATE pedidos

    SET
        status = novo_status

    WHERE
        id = pedido;

$$;

Para executar: 

CALL atualizar_status_pedido(
    10,
    'enviado'
);

Function × Procedure

Característica Function Procedure
Pode receber parâmetros Sim Sim
Pode retornar resultado Sim Depende do SGBD e da forma utilizada
Pode executar operações Sim Sim
Utilização típica Cálculos e resultados Sequência de operações
Execução Pode ser chamada em expressões, conforme o SGBD Normalmente através de CALL

Importante:

Function e Procedure não possuem exatamente o mesmo comportamento em todos os SGBDs. Sempre consulte a documentação do banco utilizado.

O que é um Trigger?

Um Trigger, ou gatilho, é um mecanismo que permite executar uma ação automaticamente quando determinado evento acontece em uma tabela ou outro objeto do banco, conforme os recursos do SGBD.

Em termos simples:

Você não precisa chamar o Trigger diretamente.

O banco dispara o Trigger quando o evento configurado acontece.

Quando um Trigger pode ser executado?

➕

INSERT

Quando um novo registro é inserido.

✏️

UPDATE

Quando um registro é atualizado.

🗑️

DELETE

Quando um registro é excluído.

Exemplo: auditoria

Imagine que uma empresa precisa registrar quando determinado registro foi alterado.

Poderíamos ter uma tabela: 

auditoria

id
tabela
operacao
data_evento

Um Trigger poderia ser utilizado para registrar automaticamente determinadas alterações.

Exemplos de utilização:
  • Auditoria de alterações.
  • Registro automático de eventos.
  • Atualização de informações derivadas.
  • Aplicação de determinadas regras.

Exemplo de Trigger no PostgreSQL

No PostgreSQL, normalmente criamos primeiro uma função que será executada pelo Trigger. 

CREATE FUNCTION registrar_data_atualizacao()

RETURNS TRIGGER

LANGUAGE plpgsql

AS $$

BEGIN

    NEW.atualizado_em = CURRENT_TIMESTAMP;

    RETURN NEW;

END;

$$;

Depois criamos o Trigger: 

CREATE TRIGGER atualizar_data

BEFORE UPDATE ON clientes

FOR EACH ROW

EXECUTE FUNCTION
registrar_data_atualizacao();

A partir desse momento, quando um cliente for atualizado, a função poderá atualizar automaticamente o campo atualizado_em.

BEFORE e AFTER

Alguns SGBDs permitem definir se o Trigger deve acontecer antes ou depois do evento.

Momento Significado
BEFORE Executa antes da operação.
AFTER Executa depois da operação.
INSTEAD OF Substitui a operação em contextos suportados pelo SGBD.

NEW e OLD

Em sistemas que utilizam esses conceitos em Triggers, NEW e OLD permitem trabalhar com os valores relacionados à operação.

Referência Representa
NEW Novo valor do registro.
OLD Valor anterior do registro.

Isso é especialmente útil para auditoria e comparação entre valores antigos e novos.

⚠️ Cuidado com Triggers

Triggers são poderosos, mas também podem tornar o comportamento do sistema mais difícil de entender quando utilizados em excesso.

🕵️

Comportamento oculto

Uma operação pode disparar outras ações automaticamente.

🔄

Dependências

Triggers podem depender de outras funções e tabelas.

🐛

Debug

Problemas podem ser mais difíceis de rastrear.

⚡

Desempenho

Uma grande quantidade de operações automáticas pode afetar o desempenho.

Não tente criar tudo de uma vez.

Primeiro faça a View funcionar. Depois crie a Function. Em seguida a Procedure. Por último, implemente o Trigger.

Boas práticas

  • Use nomes claros para Views, Functions, Procedures e Triggers.
  • Evite colocar lógica desnecessariamente complexa dentro do banco.
  • Documente regras importantes.
  • Tenha cuidado com Triggers encadeados.
  • Considere o impacto de cada recurso no desempenho.
  • Conheça as particularidades do SGBD utilizado.

Resumindo

Uma View é uma consulta armazenada que pode ser reutilizada como uma tabela virtual.

Uma Function encapsula uma lógica que pode receber parâmetros e retornar resultados.

Uma Procedure encapsula uma sequência de operações que pode ser executada sob demanda.

Um Trigger permite executar determinadas ações automaticamente em resposta a eventos.

Esses recursos fazem parte da programação de banco de dados e podem variar de sintaxe e comportamento entre diferentes SGBDs.
