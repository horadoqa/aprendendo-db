Projeto Prático: API de Loja com MongoDB

Vamos juntar os conhecimentos das aulas anteriores construindo a estrutura de um sistema de loja utilizando MongoDB.

🎯 Objetivos da aula

Nesta aula vamos deixar a teoria um pouco de lado e pensar como um desenvolvedor que precisa construir uma aplicação real.

Nosso projeto será uma pequena API de uma loja virtual.

🏪 O projeto

Imagine que uma empresa contratou você para desenvolver o backend de uma pequena loja virtual.

O sistema precisa permitir:

  • Cadastrar clientes.
  • Cadastrar produtos.
  • Consultar produtos.
  • Atualizar produtos.
  • Remover produtos.
  • Criar pedidos.
  • Consultar pedidos.
  • Calcular informações sobre vendas.
  • Proteger o acesso ao banco.

📦 Coleção de produtos

Um produto pode possuir informações como: 

{
    nome: "Notebook",
    categoria: "Eletrônicos",
    preco: 3500,
    estoque: 10,
    ativo: true
}

Diferentemente de uma tabela relacional tradicional, o documento MongoDB pode armazenar essa estrutura diretamente como um documento BSON.

👤 Coleção de usuários

Para os usuários, podemos armazenar informações como: 

{
    nome: "Ana Silva",
    email: "ana@email.com",
    ativo: true
}
Atenção:

Em uma aplicação real, senhas não devem ser armazenadas em texto puro.

Elas devem ser tratadas utilizando mecanismos apropriados de hash de senha.

🛒 Coleção de pedidos

Um pedido pode possuir informações sobre o cliente, produtos comprados, valores e status. 

{
    clienteId: ObjectId("..."),

    itens: [

        {
            produtoId: ObjectId("..."),
            quantidade: 2,
            preco: 150
        },

        {
            produtoId: ObjectId("..."),
            quantidade: 1,
            preco: 300

    ],

    status: "pago",

    total: 600,

    criadoEm: ISODate("2026-01-10")
}

Observe que o campo itens é um array de objetos.

🔄 CRUD dos produtos

Nosso primeiro objetivo será implementar as quatro operações fundamentais.

🟢 Create

Criar produtos.

🔵 Read

Consultar produtos.

🟡 Update

Atualizar produtos.

🔴 Delete

Remover produtos.

🟢 Create — Criando um produto

Podemos inserir um documento utilizando: 

db.produtos.insertOne({

    nome: "Teclado Mecânico",

    categoria: "Periféricos",

    preco: 350,

    estoque: 25,

    ativo: true

})

🔵 Read — Consultando produtos

Para consultar produtos: 

db.produtos.find()

Podemos também buscar apenas produtos ativos: 

db.produtos.find({

    ativo: true

})

Ou procurar produtos dentro de uma faixa de preço: 

db.produtos.find({

    preco: {
        $gte: 100,
        $lte: 500
    }

})

🟡 Update — Atualizando produtos

Imagine que precisamos alterar o estoque. 

db.produtos.updateOne(

    { nome: "Teclado Mecânico" },

    {
        $set: {
            estoque: 20
        }
    }

)

O operador $set altera o campo indicado sem substituir todo o documento.

🔴 Delete — Removendo produtos

Para remover um documento: 

db.produtos.deleteOne({

    nome: "Teclado Mecânico"

})
⚠️ Cuidado!

Operações de exclusão devem ser utilizadas com atenção, principalmente em produção.

🔎 Consultas mais úteis

Nossa API precisará de consultas diferentes. 

// Produtos ativos

db.produtos.find({
    ativo: true
})


// Produtos de uma categoria

db.produtos.find({
    categoria: "Periféricos"
})


// Produtos acima de R$ 500

db.produtos.find({
    preco: {
        $gt: 500
    }
})


// Produtos com estoque

db.produtos.find({
    estoque: {
        $gt: 0
    }
})

📊 Ordenação e limite

Podemos ordenar os produtos por preço. 

db.produtos
    .find()
    .sort({
        preco: -1
    })

E limitar a quantidade de resultados: 

db.produtos
    .find()
    .sort({
        preco: -1
    })
    .limit(10)

Isso pode ser utilizado, por exemplo, para montar uma página com os produtos mais caros.

📄 Paginação

Imagine que existem milhares de produtos. Não seria interessante retornar todos de uma vez.

Uma estratégia simples utiliza: 

skip()
limit()

Exemplo: 

db.produtos
    .find()
    .skip(20)
    .limit(10)

Nesse exemplo, podemos interpretar a consulta como uma forma simples de buscar uma página posterior dos resultados.

Em sistemas muito grandes, existem estratégias de paginação mais eficientes do que depender apenas de skip().

📈 Relatórios com Aggregation Pipeline

Agora podemos utilizar o conhecimento da Aggregation Pipeline.

Imagine que queremos descobrir quanto cada categoria possui em estoque. 

db.produtos.aggregate([

    {
        $group: {
            _id: "$categoria",

            quantidade: {
                $sum: "$estoque"
            }
        }
    }

])

Podemos também calcular o preço médio: 

db.produtos.aggregate([

    {
        $group: {
            _id: "$categoria",

            precoMedio: {
                $avg: "$preco"
            }
        }
    }

])

💰 Relatório de vendas

Imagine que queremos descobrir o valor total dos pedidos agrupados por status. 

db.pedidos.aggregate([

    {
        $group: {

            _id: "$status",

            total: {
                $sum: "$total"
            }

        }
    }

])

Essa mesma ideia pode ser utilizada para criar dashboards e relatórios.

⚡ Índices

Imagine que a aplicação consulta produtos constantemente pelo nome.

Podemos criar um índice: 

db.produtos.createIndex({

    nome: 1

})

Depois podemos verificar os índices: 

db.produtos.getIndexes()
Índices podem acelerar consultas, mas também possuem custo de armazenamento e manutenção.

📤 Resposta da API

A API pode retornar o produto em formato JSON: 

{
    "id": "65abc123",
    "nome": "Teclado Mecânico",
    "categoria": "Periféricos",
    "preco": 350,
    "estoque": 20,
    "ativo": true
}

✅ Validação dos dados

Antes de inserir um produto, precisamos verificar se os dados são válidos.

Por exemplo:

  • Nome é obrigatório.
  • Preço deve ser maior que zero.
  • Estoque não pode ser negativo.
  • Categoria deve ser válida.
  • Campos inesperados podem ser rejeitados. 
{
    nome: "Teclado",
    preco: 350,
    estoque: 10
}
