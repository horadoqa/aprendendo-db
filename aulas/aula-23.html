🔎 Como o MongoDB encontra um documento?

Imagine uma coleção com milhões de documentos.

Queremos encontrar um usuário específico: 

db.usuarios.findOne({
    email: "ana@email.com"
})

A pergunta é:

Como o MongoDB encontra esse documento?

Isso depende da estrutura da coleção e dos índices disponíveis.

🐢 Collection Scan

Quando uma consulta não possui um índice adequado, o MongoDB pode precisar examinar muitos documentos da coleção para encontrar os que correspondem ao filtro.

Esse tipo de operação é conhecido como collection scan. 

db.usuarios.find({
    email: "ana@email.com"
})
Imagine uma lista telefônica sem índice:

para encontrar uma pessoa, você poderia precisar verificar várias entradas até encontrar o resultado.

⚡ O que é um índice?

Um índice é uma estrutura de dados mantida pelo banco para ajudar a localizar documentos de acordo com determinados campos.

Uma analogia comum é o índice de um livro.

📖

Livro sem índice

Pode ser necessário procurar página por página.

📚

Livro com índice

O índice ajuda a localizar rapidamente onde determinado assunto aparece.

🛠️ Criando um índice

Podemos criar um índice utilizando createIndex(). 

db.usuarios.createIndex({
    email: 1
})

O número 1 representa uma ordenação crescente no índice.

Também podemos criar um índice em ordem decrescente: 

db.usuarios.createIndex({
    idade: -1
})
Importante:

O índice é criado sobre um ou mais campos e passa a fazer parte das estruturas mantidas pelo MongoDB para aquela coleção.

📋 Visualizando os índices

Podemos visualizar os índices existentes em uma coleção utilizando: 

db.usuarios.getIndexes()

Uma coleção normalmente possui um índice padrão associado ao campo _id.

🆔 O índice de _id

Todo documento do MongoDB possui, normalmente, um campo chamado _id. 

{
    _id: ObjectId("..."),
    nome: "Ana",
    email: "ana@email.com"
}

O MongoDB cria automaticamente um índice único para o campo _id.

Por isso:

você normalmente não precisa criar manualmente um índice para o campo _id.

🚀 Consulta utilizando um índice

Imagine uma coleção com muitos usuários. 

db.usuarios.createIndex({
    email: 1
})

Depois podemos executar: 

db.usuarios.find({
    email: "ana@email.com"
})

O índice pode permitir que o MongoDB encontre os documentos correspondentes sem precisar examinar todos os documentos da coleção.

🔐 Índice único

Podemos criar um índice que também exige que os valores sejam únicos. 

db.usuarios.createIndex(
    {
        email: 1
    },
    {
        unique: true
    }
)

Nesse caso, não será permitido ter múltiplos documentos com o mesmo valor de email, observadas as regras de unicidade do índice.

Exemplo:

Se um usuário já possui ana@email.com, outro documento não poderá utilizar o mesmo valor nesse índice único.

🧩 Índice composto

Um índice composto utiliza mais de um campo. 

db.usuarios.createIndex({
    cidade: 1,
    idade: -1
})

Esse índice considera a combinação entre cidade e idade.

Atenção:

A ordem dos campos em um índice composto é importante para determinar quais consultas podem aproveitá-lo de maneira eficiente.

📐 A ordem importa

Considere o índice: 

{
    cidade: 1,
    idade: 1
}

A estrutura do índice foi criada primeiro por cidade e depois por idade.

Por isso, ao planejar índices compostos, é importante considerar como as consultas realmente serão realizadas.

Campo Papel
cidade Primeiro campo do índice.
idade Segundo campo do índice.

↕️ Índices e ordenação

Índices também podem ajudar consultas que precisam ordenar resultados.

Por exemplo: 

db.produtos.find({
    categoria: "Notebook"
}).sort({
    preco: 1
})

Um índice apropriado pode ajudar o MongoDB a executar o filtro e a ordenação de maneira mais eficiente.

🔬 explain()

Como saber se uma consulta está utilizando um índice?

Uma das ferramentas mais importantes para isso é o método explain(). 

db.usuarios.find({
    email: "ana@email.com"
}).explain()

O MongoDB retorna informações sobre o plano de execução utilizado para realizar a consulta.

📊 executionStats

Para analisar mais detalhes da execução, podemos utilizar: 

db.usuarios.find({
    email: "ana@email.com"
}).explain("executionStats")

Entre as informações disponíveis estão métricas relacionadas à execução da consulta.

nReturned

Quantidade de documentos retornados.

totalDocsExamined

Quantidade de documentos examinados.

totalKeysExamined

Quantidade de entradas de índice examinadas.

executionTimeMillis

Tempo de execução reportado pelo plano.

🐢 COLLSCAN

Quando o plano de execução utiliza COLLSCAN, significa que a consulta está fazendo uma varredura da coleção. 

db.usuarios.find({
    telefone: "999999999"
}).explain("executionStats")

Se não existir um índice adequado para a consulta, o MongoDB pode precisar examinar documentos da coleção.

Mas atenção:

COLLSCAN não significa automaticamente que a consulta está errada ou que precisa de um índice. Em coleções pequenas, por exemplo, uma varredura pode ser perfeitamente adequada.

⚡ IXSCAN

IXSCAN indica que o plano está percorrendo um índice. 

db.usuarios.find({
    email: "ana@email.com"
}).explain("executionStats")

Se houver um índice adequado sobre email, o plano pode utilizar esse índice para localizar os documentos.

⚠️ Índices não são magia

Criar índices indiscriminadamente não torna automaticamente o sistema mais rápido.

Índices possuem custos.

💾

Espaço

Índices ocupam memória e armazenamento.

✏️

Escrita

Inserções, atualizações e exclusões precisam manter os índices correspondentes.

🧩

Complexidade

Muitos índices podem dificultar a estratégia de manutenção e análise do banco.

🚨 O problema de criar índices demais

Imagine uma coleção: 

usuarios

nome
email
idade
cidade
telefone
profissao
dataCadastro

Não significa que devemos criar um índice para cada campo.

O ideal é analisar as consultas reais da aplicação e criar índices que atendam às necessidades do sistema.

Regra prática:

Índices devem existir por uma razão. Não crie índices simplesmente porque um campo existe.

🧠 Quando considerar um índice?

  • Quando um campo é frequentemente utilizado em filtros.
  • Quando consultas precisam ordenar frequentemente por determinado campo.
  • Quando uma combinação específica de campos aparece frequentemente nas consultas.
  • Quando uma restrição de unicidade é necessária.
  • Quando a análise do desempenho indica que determinado índice pode ajudar.

🗑️ Removendo um índice

Para remover um índice específico, podemos utilizar: 

db.usuarios.dropIndex({
    email: 1
})

Também é possível utilizar o nome do índice. 

db.usuarios.dropIndex(
    "email_1"
)

Antes de remover um índice em um sistema real, é importante verificar quais consultas dependem dele.

🧩 Performance começa na modelagem

📝 Resumindo

Um índice é uma estrutura que pode ajudar o MongoDB a localizar documentos de forma mais eficiente para determinadas consultas.

O método createIndex() cria índices.

Índices podem ser simples, compostos ou únicos, entre outras possibilidades.

explain() permite analisar o plano de execução de uma consulta.

COLLSCAN representa uma varredura da coleção, enquanto IXSCAN indica uma varredura de índice.

Índices podem melhorar determinadas consultas, mas também ocupam recursos e precisam ser mantidos durante operações de escrita.

Performance deve ser analisada considerando consultas, índices, modelagem e infraestrutura.
