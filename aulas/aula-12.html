AULA 12 • TRANSAÇÕES E ACID

Transações e ACID

Entenda como o banco de dados garante que operações sejam executadas de forma segura, consistente e confiável.

Objetivos da aula

Em aplicações reais, uma operação geralmente envolve mais de uma alteração no banco de dados.

Imagine uma transferência bancária: precisamos retirar dinheiro de uma conta e adicionar esse dinheiro em outra. Essas duas operações precisam ser tratadas como uma unidade.

🔄

Transações

Agrupar operações que devem ser tratadas como uma unidade.

💾

COMMIT

Confirmar definitivamente as alterações.

↩️

ROLLBACK

Desfazer alterações da transação.

🛡️

ACID

Propriedades que ajudam a garantir transações confiáveis.

O problema de várias operações

Imagine uma transferência de R$ 500 entre duas contas.

Conta A: R$ 2.000

Conta B: R$ 1.000

A transferência precisa realizar pelo menos duas operações: 

UPDATE contas
SET saldo = saldo - 500
WHERE id = 1;


UPDATE contas
SET saldo = saldo + 500
WHERE id = 2;

Mas imagine que a primeira operação funcione e a segunda falhe.

Problema:

O dinheiro seria retirado da primeira conta, mas não seria adicionado à segunda.

É exatamente esse tipo de situação que as transações ajudam a evitar.

O que é uma transação?

Uma transação é um conjunto de operações que o banco de dados trata como uma unidade lógica de trabalho.

Em termos simples:

Ou todas as operações necessárias são confirmadas, ou as alterações da transação podem ser desfeitas, conforme as regras e capacidades do SGBD.

Uma transação normalmente possui três momentos importantes:

▶️

BEGIN

Inicia a transação.

✅

COMMIT

Confirma as alterações.

↩️

ROLLBACK

Desfaz as alterações da transação.

BEGIN

O comando utilizado para iniciar uma transação depende do SGBD.

Em muitos bancos podemos utilizar: 

BEGIN;

A partir desse momento, as operações realizadas fazem parte da transação atual.

COMMIT

O COMMIT confirma as alterações realizadas pela transação. 

BEGIN;

UPDATE contas
SET saldo = saldo - 500
WHERE id = 1;

UPDATE contas
SET saldo = saldo + 500
WHERE id = 2;

COMMIT;

Depois do COMMIT, as alterações da transação são confirmadas de acordo com o comportamento do SGBD e da configuração utilizada.

ROLLBACK

O ROLLBACK é utilizado para desfazer as alterações realizadas na transação que ainda não foram confirmadas. 

BEGIN;

UPDATE contas
SET saldo = saldo - 500
WHERE id = 1;

UPDATE contas
SET saldo = saldo + 500
WHERE id = 2;

ROLLBACK;

Nesse exemplo, as alterações realizadas dentro da transação são desfeitas.

COMMIT × ROLLBACK

Comando Função
BEGIN Inicia uma transação.
COMMIT Confirma as alterações da transação.
ROLLBACK Desfaz alterações não confirmadas da transação.

O que significa ACID?

ACID é um acrônimo utilizado para representar quatro propriedades associadas à confiabilidade das transações em bancos de dados.

🧱

A — Atomicidade

A transação é tratada como uma unidade: suas operações não devem produzir um estado parcialmente aplicado quando ocorre uma falha, dentro das garantias do SGBD.

✔️

C — Consistência

A transação deve levar o banco de um estado válido para outro estado válido, respeitando as regras e restrições definidas.

👥

I — Isolamento

Transações concorrentes possuem mecanismos para controlar como suas operações podem observar umas às outras.

💾

D — Durabilidade

Depois da confirmação da transação, suas alterações devem permanecer disponíveis mesmo após determinadas falhas.

A — Atomicidade

A ideia de atomicidade é que uma transação seja tratada como uma unidade de trabalho.

Tudo ou nada.

Se uma operação crítica da transação falhar, o objetivo é evitar que a transação fique parcialmente aplicada.

Exemplo: 

Transferência

Conta A
    - R$ 500

Conta B
    + R$ 500

As duas alterações fazem parte da mesma operação lógica.

C — Consistência

Consistência significa que as regras definidas para o banco devem continuar sendo respeitadas.

Por exemplo, imagine uma tabela: 

usuarios

id
nome
email

Se email possuir uma restrição UNIQUE, não devemos terminar uma transação com dois usuários utilizando o mesmo valor de e-mail.

Constraints como PRIMARY KEY, FOREIGN KEY, UNIQUE e CHECK ajudam o banco a preservar regras de integridade.

I — Isolamento

Em um sistema real, várias pessoas podem utilizar a aplicação ao mesmo tempo.

Isso significa que várias transações podem estar acontecendo simultaneamente.

Exemplo:

Dois usuários tentam comprar o último produto disponível no estoque ao mesmo tempo.

O banco precisa controlar a concorrência para evitar situações inconsistentes, de acordo com o nível de isolamento configurado.

Níveis de isolamento

Os padrões SQL definem diferentes níveis de isolamento. Os nomes mais conhecidos são:

Nível Ideia geral
READ UNCOMMITTED Permite o menor isolamento entre os níveis padronizados.
READ COMMITTED Uma transação normalmente não lê dados não confirmados de outra.
REPEATABLE READ Fornece garantias mais fortes para leituras repetidas.
SERIALIZABLE Busca o nível mais forte de isolamento, aproximando o comportamento de execução serializada.

Importante:

O comportamento exato pode variar entre SGBDs, especialmente em relação a locks, MVCC e detalhes de implementação.

D — Durabilidade

Depois que uma transação é confirmada, o banco deve fornecer mecanismos para preservar suas alterações mesmo diante de determinadas falhas.

Exemplo:

Uma aplicação registra um pagamento e recebe confirmação de que a transação foi concluída.

Um problema posterior no servidor não deve simplesmente apagar a transação já confirmada.

ACID em uma tabela

Letra Conceito Ideia principal
A Atomicidade Unidade de trabalho.
C Consistência Preservar regras e integridade.
I Isolamento Controlar a interação entre transações concorrentes.
D Durabilidade Preservar alterações confirmadas.

SAVEPOINT

Alguns SGBDs permitem criar pontos intermediários dentro de uma transação utilizando SAVEPOINT.

Isso permite desfazer parte do trabalho sem necessariamente cancelar toda a transação. 

BEGIN;

UPDATE produtos
SET estoque = estoque - 1
WHERE id = 10;

SAVEPOINT estoque_atualizado;

UPDATE pedidos
SET status = 'processando'
WHERE id = 100;

ROLLBACK TO SAVEPOINT estoque_atualizado;

COMMIT;

O suporte e a sintaxe podem variar conforme o SGBD.

O que é Auto Commit?

Muitos ambientes trabalham com autocommit, no qual determinadas instruções são confirmadas automaticamente.

Por isso, é importante entender como o cliente, driver e SGBD utilizados estão configurados antes de executar operações críticas.

Em exercícios de transações, normalmente é mais didático controlar explicitamente: 

BEGIN;

-- operações

COMMIT;

-- ou

ROLLBACK;

Exemplo completo: transferência

Vamos montar uma transação de transferência entre duas contas. 

BEGIN;

UPDATE contas
SET saldo = saldo - 500
WHERE id = 1
  AND saldo >= 500;


UPDATE contas
SET saldo = saldo + 500
WHERE id = 2;


COMMIT;
Atenção:

Em uma aplicação real, ainda precisamos validar situações como conta inexistente, saldo insuficiente, concorrência e falhas entre operações.

Transações e aplicações

Normalmente, a aplicação inicia uma transação, executa operações e decide se deve confirmar ou desfazer o trabalho.

📱

Aplicação

Solicita as operações ao banco.

🗄️

Banco de dados

Executa as operações dentro da transação.

✅

Sucesso

A aplicação confirma com COMMIT.

↩️

Falha

A aplicação pode utilizar ROLLBACK, quando apropriado.

Quando devemos utilizar transações?

  • 💳 Processamento de pagamentos.
  • 🏦 Transferências financeiras.
  • 🛒 Criação de pedidos e atualização de estoque.
  • 🎫 Reserva de ingressos ou vagas.
  • 📦 Movimentação de estoque.
  • 👤 Operações que alteram várias tabelas de forma relacionada.

🎯 Desafio da aula

Imagine um pequeno sistema de vendas.

Quando um cliente realiza uma compra, o sistema precisa:

  • Registrar os itens do pedido.

Como uma transação poderia ajudar nesse cenário?

Boas práticas com transações

  • Mantenha transações tão curtas quanto possível.
  • Não mantenha uma transação aberta sem necessidade.
  • Defina claramente quais operações fazem parte da mesma unidade de trabalho.
  • Trate erros corretamente na aplicação.
  • Conheça o nível de isolamento utilizado.
  • Entenda o comportamento específico do SGBD.
  • Teste cenários de concorrência e falha.

Resumindo

Uma transação agrupa operações relacionadas em uma unidade lógica de trabalho.

COMMIT confirma as alterações da transação.

ROLLBACK desfaz alterações não confirmadas.

ACID representa quatro propriedades importantes associadas à confiabilidade das transações: Atomicidade, Consistência, Isolamento e Durabilidade.

Transações são fundamentais em operações como pagamentos, transferências, pedidos e movimentações de estoque.
