🐌 O problema das consultas sem índice

Imagine uma coleção contendo milhões de documentos.

Queremos encontrar um usuário específico: 

db.usuarios.find({

    email: "ana@email.com"

})

Sem um índice adequado, o banco pode precisar analisar muitos documentos até encontrar os registros que correspondem à consulta.

Imagine uma biblioteca.

Procurar um livro específico examinando livro por livro seria muito demorado.

Um catálogo permite encontrar rapidamente onde aquele livro está.

Um índice funciona de maneira semelhante: ele cria uma estrutura que ajuda o MongoDB a localizar os documentos necessários.

📚 O que é um índice?

Um índice é uma estrutura de dados mantida pelo MongoDB para permitir que determinadas consultas encontrem documentos de maneira mais eficiente.

Por exemplo, podemos criar um índice no campo email: 

db.usuarios.createIndex({

    email: 1

})

O número 1 representa uma ordenação crescente no índice.

Também podemos utilizar -1: 

db.usuarios.createIndex({

    email: -1

})

Nesse caso, o índice utiliza ordenação decrescente.

🔑 O índice _id

Existe um índice especial que você encontra em praticamente toda coleção MongoDB: o índice do campo _id.

Quando um documento possui um campo _id, o MongoDB cria automaticamente um índice único para esse campo. 

{
    _id: 1,

    nome: "Ana",

    email: "ana@email.com"
}
Importante:

O índice de _id não precisa ser criado manualmente.

🛠️ Criando um índice

O método utilizado para criar índices é: 

createIndex()

Exemplo: 

db.usuarios.createIndex({

    email: 1

})

Depois disso, consultas que utilizam esse campo podem se beneficiar do índice.

📋 Visualizando os índices

Podemos verificar os índices existentes em uma coleção utilizando: 

db.usuarios.getIndexes()

O MongoDB retornará informações sobre os índices existentes. 

[
    {
        v: 2,

        key: {
            _id: 1
        },

        name: "_id_"
    },

    {
        v: 2,

        key: {
            email: 1
        },

        name: "email_1"
    }
]

🔐 Índice único

Podemos criar um índice que impede valores duplicados utilizando a opção unique.

Um exemplo clássico é o e-mail de um usuário. 

db.usuarios.createIndex(

    {
        email: 1
    },

    {
        unique: true
    }

)

Depois disso, dois documentos não poderão possuir o mesmo valor de e-mail.

Índice não serve apenas para performance.

Um índice único também pode ser utilizado para impor uma regra de unicidade.

🧩 Índices compostos

Um índice pode utilizar mais de um campo. Esse tipo de índice é chamado de índice composto.

Por exemplo: 

db.usuarios.createIndex({

    cidade: 1,

    nome: 1

})

Esse índice considera os campos cidade e nome.

A ordem dos campos é importante.

Índices compostos devem ser planejados de acordo com os padrões reais de consulta da aplicação.

🔎 Exemplo de consulta com índice composto

Imagine uma coleção de pedidos: 

{
    clienteId: 100,

    status: "concluido",

    valor: 4500
}

Se uma aplicação consulta frequentemente pedidos por cliente e status, podemos considerar um índice composto: 

db.pedidos.createIndex({

    clienteId: 1,

    status: 1

})

E então realizar uma consulta como: 

db.pedidos.find({

    clienteId: 100,

    status: "concluido"

})

🔬 Analisando consultas com explain()

Criar um índice não significa simplesmente assumir que a consulta ficará mais rápida.

Precisamos analisar o comportamento da consulta.

O MongoDB fornece o método explain() para isso. 

db.usuarios.find({

    email: "ana@email.com"

}).explain("executionStats")

O resultado apresenta informações sobre como o MongoDB executou a consulta.

🔍 COLLSCAN

Um termo importante ao analisar uma consulta é COLLSCAN.

COLLSCAN significa Collection Scan.

Isso indica que o MongoDB está examinando documentos da coleção para encontrar aqueles que correspondem à consulta. 

db.usuarios.find({

    email: "ana@email.com"

}).explain("executionStats")

Se a consulta resultar em um plano baseado em COLLSCAN, pode ser necessário investigar se existe um índice adequado.

⚡ IXSCAN

Outro termo importante é IXSCAN.

IXSCAN indica que o MongoDB está percorrendo um índice para executar parte da consulta. 

db.usuarios.find({

    email: "ana@email.com"

}).explain("executionStats")
🐌

COLLSCAN

Percorre documentos da coleção.

⚡

IXSCAN

Utiliza um índice durante a execução.

📊 executionStats

Ao utilizar: 

.explain("executionStats")

podemos observar diversas informações sobre a execução.

Informação O que representa
executionTimeMillis Tempo de execução observado.
nReturned Quantidade de documentos retornados.
totalDocsExamined Quantidade de documentos examinados.
totalKeysExamined Quantidade de entradas de índice examinadas.

📉 Por que totalDocsExamined importa?

Imagine uma coleção com: 

10.000.000 documentos

E uma consulta que retorna apenas: 

1 documento

Se o MongoDB precisar examinar milhões de documentos para encontrar aquele único resultado, isso pode indicar uma oportunidade de melhoria.

A ideia não é simplesmente "usar índices em tudo".

O objetivo é criar índices que façam sentido para os padrões de consulta da aplicação.

↕️ Índices e ordenação

Índices também podem ajudar consultas que precisam ordenar resultados.

Imagine: 

db.produtos.find({

    categoria: "notebooks"

}).sort({

    preco: -1

})

Um índice que considere os campos utilizados pela consulta pode ajudar o MongoDB a processar esse tipo de operação com mais eficiência.

🗂️ Tipos de índices

O MongoDB possui diferentes recursos de indexação para diferentes necessidades.

Índice simples

Utiliza um único campo. 

{ email: 1 }

Índice composto

Utiliza múltiplos campos. 

{
    cidade: 1,
    nome: 1
}

Índice único

Impede valores duplicados. 

{
    unique: true
}

Índice de texto

Pode ser utilizado para determinadas pesquisas textuais.

🔤 Índice de texto

O MongoDB possui suporte a índices de texto para determinados cenários de pesquisa textual.

Por exemplo: 

db.artigos.createIndex({

    titulo: "text"

})

Depois podemos utilizar uma consulta de texto: 

db.artigos.find({

    $text: {
        $search: "MongoDB"
    }

})
Atenção:

Índices de texto possuem características próprias e não substituem automaticamente mecanismos especializados de busca.

⚠️ Índices também possuem custos

É tentador pensar que quanto mais índices tivermos, melhor será a aplicação.

Porém, isso não é verdade.

Índices também ocupam espaço e precisam ser mantidos quando os dados são inseridos, atualizados ou removidos.

💾

Espaço

Índices consomem armazenamento.

✏️

Escritas

Operações de escrita precisam manter os índices atualizados.

🧠

Complexidade

Muitos índices podem dificultar a manutenção e o planejamento.

🤔 Quando devemos criar um índice?

Não existe uma regra universal que determine exatamente quais campos devem receber índices.

A decisão deve considerar principalmente o comportamento da aplicação.

  • Campos frequentemente utilizados em consultas.
  • Campos utilizados para ordenação.
  • Campos utilizados em filtros importantes.
  • Campos utilizados em determinadas combinações de consultas.
  • Requisitos de unicidade.
Regra prática:

Primeiro conheça as consultas da aplicação. Depois escolha os índices que atendem a esses padrões.

🚫 Quando um índice pode não ser necessário?

Criar índices indiscriminadamente pode aumentar custos sem trazer benefícios relevantes.

Por exemplo, um campo que quase nunca participa de consultas pode não justificar um índice.

Também devemos considerar o tamanho e o comportamento da coleção.

Índice é uma ferramenta de otimização.

Ele deve existir para atender uma necessidade real da aplicação.

🗑️ Removendo um índice

Quando um índice deixa de ser necessário, podemos removê-lo.

Primeiro podemos verificar os índices existentes: 

db.usuarios.getIndexes()

Depois podemos remover um índice pelo nome: 

db.usuarios.dropIndex("email_1")

O nome do índice pode ser encontrado no resultado de getIndexes().

🔥 Exemplo completo

Imagine uma aplicação que possui milhões de pedidos.

Frequentemente precisamos buscar pedidos de um determinado cliente: 

db.pedidos.find({

    clienteId: 1001

})

Podemos criar: 

db.pedidos.createIndex({

    clienteId: 1

})

Depois podemos analisar a consulta: 

db.pedidos.find({

    clienteId: 1001

}).explain("executionStats")

A partir das informações retornadas pelo explain(), podemos avaliar como a consulta está sendo executada.

🔄 Um fluxo para otimizar consultas

1️⃣ Observar

Identifique consultas importantes da aplicação.

2️⃣ Medir

Utilize explain() para analisar a execução.

3️⃣ Planejar

Escolha índices compatíveis com os padrões de consulta.

4️⃣ Testar

Compare o comportamento antes e depois da alteração.

📝 Resumindo

Um índice é uma estrutura que pode ajudar o MongoDB a localizar dados de maneira mais eficiente.

O método createIndex() é utilizado para criar índices.

O método getIndexes() permite visualizar os índices existentes.

O explain() permite analisar como uma consulta foi executada.

COLLSCAN representa uma varredura da coleção, enquanto IXSCAN indica a utilização de um índice em uma etapa da execução.

Índices podem melhorar consultas, mas também possuem custos de armazenamento e manutenção.

Por isso, bons índices devem ser escolhidos considerando os padrões reais de consulta da aplicação.
