O que é um Banco de Dados Relacional?

Um banco de dados relacional organiza os dados principalmente em estruturas chamadas tabelas.

Essas tabelas podem representar diferentes entidades de um sistema, como clientes, produtos, pedidos e funcionários.

Ideia principal:

Um banco relacional organiza os dados em tabelas e permite estabelecer relações entre essas tabelas.

O que é uma tabela?

Uma tabela é uma estrutura utilizada para organizar informações relacionadas a um determinado assunto.

Por exemplo, podemos ter uma tabela chamada clientes.

ID Nome E-mail Cidade
1 Ana Silva ana@email.com Rio de Janeiro
2 João Santos joao@email.com São Paulo
3 Maria Oliveira maria@email.com Belo Horizonte

Essa tabela representa informações sobre clientes. Cada cliente possui seus próprios valores.

O que são colunas?

As colunas representam os atributos ou características que queremos armazenar.

Na tabela de clientes, por exemplo:

🆔

ID

Identifica o cliente.

👤

Nome

Armazena o nome do cliente.

📧

E-mail

Armazena o endereço de e-mail.

📍

Cidade

Armazena a cidade do cliente.

Regra mental:

Coluna = característica que queremos armazenar.

O que são registros?

Um registro representa uma ocorrência armazenada em uma tabela.

Em uma tabela de clientes, cada registro pode representar um cliente.

ID Nome E-mail Cidade
1 Ana Silva ana@email.com Rio de Janeiro

A linha acima representa um registro da tabela clientes.

Nesse caso, o registro representa a cliente Ana Silva.

Em uma explicação introdutória, também é comum utilizar o termo linha como sinônimo de registro.

Tabela, coluna e registro

Conceito Significado Exemplo
Tabela Estrutura que organiza os dados. clientes
Coluna Atributo armazenado. nome
Registro Uma ocorrência armazenada. Ana Silva
Valor Dado armazenado em uma coluna de um registro. Rio de Janeiro

O que é uma chave primária?

A chave primária, ou Primary Key (PK), é utilizada para identificar de maneira única cada registro de uma tabela.

Na nossa tabela de clientes, podemos utilizar a coluna ID como chave primária.

ID Nome E-mail
1 Ana Silva ana@email.com
2 João Santos joao@email.com
3 Maria Oliveira maria@email.com
Por que isso é importante?

Se quisermos localizar o cliente de ID 2, sabemos exatamente qual registro estamos procurando.

Características de uma chave primária

Uma chave primária deve permitir identificar inequivocamente cada registro da tabela.

1️⃣

Identificação

Identifica um registro dentro da tabela.

🚫

Unicidade

Não deve existir mais de um registro com a mesma chave primária.

🎯

Precisão

Permite identificar exatamente o registro desejado.

Por que criar várias tabelas?

Um sistema normalmente precisa armazenar diferentes tipos de informações.

Uma loja, por exemplo, pode ter:

👥

clientes

Informações dos clientes.

📦

produtos

Informações dos produtos.

🛒

pedidos

Informações dos pedidos.

Essas informações estão relacionadas entre si. Um cliente pode realizar vários pedidos, por exemplo.

O que é uma chave estrangeira?

Uma chave estrangeira, ou Foreign Key (FK), é utilizada para estabelecer uma relação entre tabelas.

Imagine que temos estas duas tabelas:

Tabela clientes

ID Nome
1 Ana Silva
2 João Santos

Tabela pedidos

ID cliente_id valor
101 1 250,00
102 1 150,00
103 2 320,00

A coluna cliente_id da tabela pedidos pode funcionar como uma chave estrangeira que referencia o ID da tabela clientes.

Dessa forma, conseguimos representar que um pedido pertence a determinado cliente.

Como as tabelas se relacionam?

Podemos visualizar o exemplo anterior de maneira simplificada:

🛒 Pedidos

Um cliente pode possuir vários pedidos.

Esse tipo de relação é chamado de um para muitos (1:N).

Os diferentes tipos de relacionamento serão estudados com mais detalhes em uma aula específica.

Como isso aparece no SQL?

Uma tabela pode ser criada utilizando SQL. 

CREATE TABLE clientes (
    id INTEGER PRIMARY KEY,
    nome VARCHAR(100),
    email VARCHAR(150),
    cidade VARCHAR(100)
);

Nesse exemplo:

  • clientes é o nome da tabela.
  • id é uma coluna utilizada como chave primária.
  • nome armazena o nome do cliente.
  • email armazena o e-mail.
  • cidade armazena a cidade.

O que são tipos de dados?

Cada coluna normalmente possui um tipo de dado definido para indicar quais valores podem ser armazenados nela.

Tipo Exemplo Uso
INTEGER 10 Números inteiros.
VARCHAR "Ana" Textos.
DATE 2026-01-20 Datas.
BOOLEAN TRUE Valores verdadeiro/falso.

Os tipos disponíveis e seus detalhes podem variar de acordo com o SGBD utilizado.

Montando um pequeno banco de dados

Imagine uma pequena loja virtual.

Podemos começar identificando algumas entidades:

👤

Clientes

Quem compra na loja.

📦

Produtos

O que a loja vende.

🛒

Pedidos

Compras realizadas pelos clientes.

Essas entidades podem ser representadas por tabelas diferentes e relacionadas por meio de chaves.

⚠️ Uma diferença importante

Tabela não é banco de dados.

Uma tabela é apenas uma das estruturas utilizadas para organizar dados dentro de um banco de dados relacional.

Um banco de dados pode possuir várias tabelas, além de outros objetos e estruturas.
