O que é uma subconsulta?

Uma subconsulta, também chamada de subquery, é uma consulta SQL colocada dentro de outra consulta.

Em termos simples:

É uma consulta que ajuda outra consulta a encontrar ou calcular os dados necessários.

Podemos pensar em duas etapas:

ETAPA 1

Descobrir uma informação

Executamos uma consulta para encontrar determinado valor.

ETAPA 2

Utilizar essa informação

A consulta externa utiliza o resultado encontrado.

Primeiro exemplo

Imagine que queremos encontrar os pedidos que possuem valor acima da média.

Primeiro precisamos descobrir qual é a média. 

SELECT
    AVG(total)

FROM pedidos;

Depois poderíamos utilizar esse valor em outra consulta. 

SELECT
    id,
    cliente_id,
    total

FROM pedidos

WHERE total > 323.33;

Mas existe uma maneira de fazer isso diretamente com uma subconsulta. 

SELECT
    id,
    cliente_id,
    total

FROM pedidos

WHERE total > (

    SELECT
        AVG(total)

    FROM pedidos

);
O que aconteceu?

A consulta interna calcula a média.

A consulta externa utiliza essa média para filtrar os pedidos.

Subconsulta no WHERE

Um dos usos mais comuns de subconsultas é dentro da cláusula WHERE.

Imagine que queremos encontrar os clientes que possuem pelo menos um pedido. 

SELECT
    nome

FROM clientes

WHERE id IN (

    SELECT
        cliente_id

    FROM pedidos

);

A consulta interna retorna os IDs dos clientes que aparecem na tabela de pedidos.

A consulta externa procura esses clientes na tabela clientes.

IN

O operador IN verifica se um valor pertence a uma lista de valores.

Podemos utilizar essa lista diretamente: 

SELECT
    nome

FROM clientes

WHERE cidade IN (
    'São Paulo',
    'Rio de Janeiro'
);

Também podemos obter essa lista através de uma subconsulta. 

SELECT
    nome

FROM clientes

WHERE id IN (

    SELECT
        cliente_id

    FROM pedidos

    WHERE total > 1000

);

Essa consulta encontra clientes que possuem pelo menos um pedido acima de R$ 1.000.

NOT IN

O NOT IN faz o contrário: verifica se um valor não está presente na lista. 

SELECT
    nome

FROM clientes

WHERE id NOT IN (

    SELECT
        cliente_id

    FROM pedidos

);
Atenção ao NULL:

NOT IN pode produzir resultados inesperados quando a subconsulta retorna valores NULL. Por isso, em consultas reais, muitas vezes EXISTS ou NOT EXISTS é uma alternativa mais segura.

EXISTS

O EXISTS verifica se a subconsulta retorna pelo menos uma linha.

Podemos encontrar clientes que possuem pedidos: 

SELECT
    c.nome

FROM clientes c

WHERE EXISTS (

    SELECT 1

    FROM pedidos p

    WHERE p.cliente_id = c.id

);
Ideia principal:

"Existe pelo menos um pedido relacionado a este cliente?"

NOT EXISTS

O NOT EXISTS verifica se a subconsulta não retorna nenhuma linha.

Podemos encontrar clientes que ainda não possuem pedidos: 

SELECT
    c.nome

FROM clientes c

WHERE NOT EXISTS (

    SELECT 1

    FROM pedidos p

    WHERE p.cliente_id = c.id

);

Subconsulta escalar

Uma subconsulta escalar retorna um único valor.

Por exemplo: 

SELECT

    nome,

    (
        SELECT
            COUNT(*)

        FROM pedidos p

        WHERE
            p.cliente_id = c.id
    ) AS quantidade_pedidos

FROM clientes c;

A subconsulta calcula a quantidade de pedidos de cada cliente.

Esse tipo de consulta é útil, mas dependendo do problema, um JOIN com GROUP BY pode ser mais apropriado.

Subconsulta no FROM

Uma subconsulta também pode aparecer no FROM.

Nesse caso, o resultado da subconsulta funciona como uma tabela temporária para aquela consulta. 

SELECT
    cliente_id,
    total_gasto

FROM (

    SELECT

        cliente_id,

        SUM(total) AS total_gasto

    FROM pedidos

    GROUP BY cliente_id

) AS resumo;

Primeiro a consulta interna calcula o total por cliente.

Depois a consulta externa trabalha com esse resultado como se fosse uma tabela.

O problema das subconsultas grandes

Subconsultas são muito úteis, mas consultas grandes podem ficar difíceis de ler quando possuem várias camadas.

Por exemplo: 

SELECT
    ...

FROM (

    SELECT
        ...

    FROM (

        SELECT
            ...

        FROM (

            SELECT
                ...

        ) AS etapa1

    ) AS etapa2

) AS etapa3;

Quanto mais níveis adicionamos, mais difícil pode ser entender e manter a consulta.

É aqui que entram as CTEs.

O que é uma CTE?

CTE significa Common Table Expression.

Em SQL, uma CTE permite definir um resultado temporário com um nome e depois utilizá-lo dentro da consulta principal.

Em termos simples:

Uma CTE permite transformar uma consulta complexa em etapas nomeadas.

A estrutura básica utiliza a palavra-chave WITH. 

WITH nome_da_cte AS (

    SELECT
        ...

)

SELECT
    ...

FROM nome_da_cte;

Primeira CTE

Vamos transformar o exemplo anterior em uma CTE. 

WITH resumo AS (

    SELECT

        cliente_id,

        SUM(total) AS total_gasto

    FROM pedidos

    GROUP BY cliente_id

)

SELECT

    cliente_id,

    total_gasto

FROM resumo;

A CTE chamada resumo funciona como uma tabela temporária dentro daquela consulta.

WITH → cria a CTE.

resumo → nome da CTE.

AS → define a consulta que produz seus dados.

CTE com filtro

Podemos utilizar a CTE e depois aplicar filtros sobre seu resultado. 

WITH resumo AS (

    SELECT

        cliente_id,

        SUM(total) AS total_gasto

    FROM pedidos

    GROUP BY cliente_id

)

SELECT

    cliente_id,

    total_gasto

FROM resumo

WHERE total_gasto > 1000;

CTE com JOIN

Agora podemos relacionar o resultado da CTE com a tabela de clientes. 

WITH resumo AS (

    SELECT

        cliente_id,

        SUM(total) AS total_gasto

    FROM pedidos

    GROUP BY cliente_id

)

SELECT

    c.nome,

    r.total_gasto

FROM clientes c

INNER JOIN resumo r
    ON c.id = r.cliente_id

ORDER BY
    r.total_gasto DESC;

Primeiro calculamos o total por cliente.

Depois relacionamos esse resultado com a tabela de clientes.

Utilizando várias CTEs

Uma das grandes vantagens das CTEs é poder criar várias etapas nomeadas na mesma consulta. 

WITH

resumo_pedidos AS (

    SELECT

        cliente_id,

        COUNT(*) AS quantidade,

        SUM(total) AS total_gasto

    FROM pedidos

    GROUP BY cliente_id

),


clientes_ativos AS (

    SELECT

        cliente_id,

        quantidade,

        total_gasto

    FROM resumo_pedidos

    WHERE quantidade > 2

)


SELECT

    c.nome,

    ca.quantidade,

    ca.total_gasto

FROM clientes c

INNER JOIN clientes_ativos ca
    ON c.id = ca.cliente_id

ORDER BY
    ca.total_gasto DESC;

Observe que cada etapa possui um nome.

resumo_pedidos → calcula as informações dos pedidos.

clientes_ativos → filtra o resultado anterior.

Consulta final → apresenta os nomes dos clientes.

Subconsulta × CTE

Sintaxe SELECT dentro de outra consulta WITH
Nome Normalmente utiliza alias Possui nome próprio
Organização Pode ficar aninhada Pode separar etapas
Legibilidade Pode ficar difícil em consultas grandes Geralmente facilita a leitura

Exemplo completo

Vamos criar uma consulta que:

  • Calcula a quantidade de pedidos por cliente.
  • Calcula o total gasto.
  • Calcula a média dos pedidos.
  • Mostra apenas clientes com mais de 2 pedidos.
  • Ordena pelo maior total gasto. 
WITH resumo AS (

    SELECT

        cliente_id,

        COUNT(*) AS quantidade_pedidos,

        SUM(total) AS total_gasto,

        AVG(total) AS media_pedidos

    FROM pedidos

    GROUP BY cliente_id

)


SELECT

    c.nome,

    r.quantidade_pedidos,

    r.total_gasto,

    r.media_pedidos

FROM clientes c

INNER JOIN resumo r
    ON c.id = r.cliente_id

WHERE
    r.quantidade_pedidos > 2

ORDER BY
    r.total_gasto DESC;
Perceba a divisão:

A CTE resolve a parte de agregação.

A consulta principal resolve a apresentação dos dados.

Quando utilizar subconsultas?

Subconsultas são úteis quando uma consulta depende diretamente do resultado de outra.

  • Comparar valores com uma média.
  • Verificar se determinados registros existem.
  • Filtrar utilizando o resultado de outra consulta.
  • Criar uma tabela derivada.

Quando utilizar CTEs?

CTEs são especialmente úteis quando queremos dividir uma consulta complexa em etapas.

  • Melhorar a organização da consulta.
  • Dar nomes para etapas intermediárias.
  • Facilitar a leitura do SQL.
  • Separar cálculos complexos.
  • Trabalhar com várias etapas de transformação.

CTE não significa necessariamente que a consulta será mais rápida.

Seu principal benefício aqui é organizar e estruturar o SQL. O comportamento de execução depende do SGBD e da própria consulta.

Resumindo

Uma subconsulta é uma consulta dentro de outra consulta.

Ela pode ser utilizada para comparar valores, filtrar registros, verificar existência ou produzir uma tabela derivada.

EXISTS verifica se uma consulta retorna pelo menos uma linha.

Uma CTE utiliza WITH para criar um resultado temporário e nomeado dentro da consulta.

CTEs são especialmente úteis para dividir consultas complexas em etapas mais fáceis de entender.

Subconsultas e CTEs não substituem os conceitos anteriores. Elas trabalham junto com SELECT, WHERE, JOIN, GROUP BY, HAVING e ORDER BY.
