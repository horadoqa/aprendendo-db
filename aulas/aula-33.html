DuckDB + Parquet

Aprenda a consultar arquivos Parquet diretamente usando SQL com o DuckDB.

🦆 O que é DuckDB?

DuckDB é um banco de dados analítico projetado para executar consultas de forma eficiente, especialmente em cargas de trabalho analíticas.

Ele pode funcionar dentro de aplicações e ferramentas de análise de dados sem exigir uma arquitetura tradicional de servidor de banco de dados para começar a trabalhar.

Uma ideia importante:

DuckDB permite utilizar SQL para analisar dados armazenados em arquivos, incluindo arquivos Parquet.

🧩 DuckDB x Parquet

É importante não confundir os dois.

Tecnologia O que é?
Parquet Formato de arquivo para armazenamento eficiente de dados.
DuckDB Sistema de banco de dados analítico que pode consultar e processar dados.
SQL Linguagem utilizada para realizar consultas e manipular dados.

Podemos pensar de maneira simplificada:

Parquet = onde os dados estão armazenados.

DuckDB = ferramenta que pode consultar esses dados.

SQL = linguagem utilizada para fazer a consulta.

O arquivo Parquet contém os dados.

O DuckDB processa esses dados.

O SQL descreve o que queremos consultar.

📁 Nosso arquivo de exemplo

Imagine que temos um arquivo chamado: 

vendas.parquet

Ele contém milhões de vendas.

Cada registro possui informações como: 

id
cliente_id
produto
categoria
cidade
data
quantidade
preco

🔎 Primeiro SELECT

Podemos consultar o arquivo Parquet utilizando uma instrução SQL. 

SELECT *
FROM 'vendas.parquet';

A ideia é simples:

  • SELECT indica quais dados queremos.
  • * significa todas as colunas.
  • FROM indica a origem dos dados.
  • 'vendas.parquet' é o arquivo que será consultado.

🎯 Selecionando apenas algumas colunas

Não precisamos consultar todas as colunas. 

SELECT
    produto,
    categoria,
    preco
FROM 'vendas.parquet';

Dessa forma estamos interessados apenas em:

  • Produto
  • Categoria
  • Preço
Esse é um dos pontos interessantes do armazenamento colunar: ferramentas podem aproveitar a estrutura do arquivo para trabalhar apenas com as colunas necessárias.

🔍 Utilizando WHERE

Podemos filtrar os dados.

Por exemplo, queremos apenas vendas da cidade do Rio de Janeiro: 

SELECT *
FROM 'vendas.parquet'
WHERE cidade = 'Rio de Janeiro';

🔢 Utilizando LIMIT

Se o arquivo possuir milhões de registros, provavelmente não queremos visualizar tudo.

Podemos limitar o resultado: 

SELECT *
FROM 'vendas.parquet'
LIMIT 10;

Isso retorna apenas os primeiros 10 registros do resultado.

↕️ Ordenando resultados

Podemos utilizar ORDER BY. 

SELECT
    produto,
    preco
FROM 'vendas.parquet'
ORDER BY preco DESC
LIMIT 10;

Nesse exemplo estamos procurando os produtos com os maiores preços.

🔢 COUNT

Também podemos descobrir quantos registros existem. 

SELECT
    COUNT(*) AS total_vendas
FROM 'vendas.parquet';

O resultado pode ser algo como: 

total_vendas
-------------
500000000

Ou seja, nosso arquivo poderia conter 500 milhões de registros.

💰 SUM

Podemos calcular o faturamento.

Suponha que temos: 

quantidade
preco

Podemos calcular: 

SELECT
    SUM(quantidade * preco) AS faturamento
FROM 'vendas.parquet';

📊 GROUP BY

Agora vamos começar a fazer uma análise mais interessante.

Queremos descobrir o faturamento por categoria. 

SELECT
    categoria,
    SUM(quantidade * preco) AS faturamento
FROM 'vendas.parquet'
GROUP BY categoria;

O resultado poderia ser: 

categoria       faturamento
---------------------------
Eletrônicos     12500000
Informática      9800000
Celulares       15300000
Móveis           7200000

Agora temos uma combinação bastante interessante:

📦

🦆

DuckDB

Processa e consulta os dados.

💬

Permite expressar as consultas.

Resultado:

Podemos realizar análises sobre grandes conjuntos de dados utilizando uma linguagem que já conhecemos: SQL.

⚖️ CSV x Parquet na análise

Imagine dois arquivos contendo os mesmos dados: 

vendas.csv
vendas.parquet

Com DuckDB, podemos consultar os dois formatos. 

SELECT *
FROM 'vendas.csv'
LIMIT 10;

E: 

SELECT *
FROM 'vendas.parquet'
LIMIT 10;

A sintaxe básica é muito parecida.

A grande diferença está na forma como os dados são armazenados e nas características de cada formato.

📁 Consultando vários arquivos

Em projetos reais, os dados podem estar divididos em vários arquivos. 


vendas/
├── vendas_2024.parquet
├── vendas_2025.parquet
└── vendas_2026.parquet

O DuckDB pode trabalhar com múltiplos arquivos Parquet em uma única consulta. 

SELECT
    COUNT(*)
FROM 'vendas/*.parquet';

Nesse caso, o padrão *.parquet representa os arquivos que correspondem ao padrão indicado.

🗂️ Dados particionados

Em grandes ambientes de dados, os arquivos podem ser organizados em diretórios de acordo com determinadas características. 


vendas/
│
├── ano=2025/
│   ├── mes=01/
│   ├── mes=02/
│   └── mes=03/
│
└── ano=2026/
    ├── mes=01/
    ├── mes=02/
    └── mes=03/

Essa organização é conhecida como particionamento.

Particionar dados pode ajudar sistemas analíticos a evitar o processamento de arquivos que não são relevantes para determinada consulta.

🔎 Consultando apenas um período

Imagine que queremos analisar apenas as vendas de 2026. 

SELECT
    categoria,
    SUM(quantidade * preco) AS faturamento
FROM 'vendas/**/*.parquet'
WHERE ano = 2026
GROUP BY categoria;

Em arquiteturas apropriadas, a organização dos dados pode permitir que apenas as partições relevantes sejam consideradas.

🛠️ DuckDB não precisa substituir seu banco operacional

Imagine uma aplicação utilizando PostgreSQL para suas operações do dia a dia.

Nesse cenário, cada tecnologia possui uma função diferente.

  • PostgreSQL: banco operacional.
  • Parquet: formato de armazenamento.
  • DuckDB: processamento analítico.
  • SQL: linguagem de consulta.

📚 SQL que já conhecemos

Observe quantos conceitos de SQL continuam válidos:

SELECT

Escolher dados.

WHERE

Filtrar dados.

GROUP BY

Agrupar dados.

SUM / COUNT

Fazer agregações.

A linguagem continua sendo SQL. O que muda é o ambiente em que os dados estão armazenados e processados.

🚀 Exemplo completo

Vamos imaginar que queremos descobrir quais categorias geraram mais faturamento no Rio de Janeiro. 

SELECT
    categoria,
    SUM(quantidade * preco) AS faturamento
FROM 'vendas.parquet'
WHERE cidade = 'Rio de Janeiro'
GROUP BY categoria
ORDER BY faturamento DESC;

Observe a sequência:

  1. FROM → escolhemos a origem.
  2. WHERE → filtramos os dados.
  3. GROUP BY → agrupamos por categoria.
  4. SUM → calculamos o faturamento.
  5. ORDER BY → ordenamos o resultado.
