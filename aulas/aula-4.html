O que é modelagem de dados?

Modelagem de dados é o processo de analisar as informações de um sistema e definir como elas serão organizadas.

Antes de criar tabelas no banco de dados, precisamos entender o problema que estamos tentando representar.

Em termos simples:

Modelar dados é transformar uma situação do mundo real em uma estrutura que possa ser armazenada e manipulada por um banco de dados.

Imagine um sistema de uma loja

Vamos imaginar que precisamos criar o banco de dados de uma loja virtual.

O sistema precisa armazenar informações sobre:

👤

Clientes

Nome, e-mail, telefone e endereço.

📦

Produtos

Nome, descrição, preço e estoque.

🛒

Pedidos

Data, valor e cliente responsável.

💳

Pagamentos

Forma de pagamento e situação da cobrança.

Primeiro passo: entender o problema

Um erro comum é começar imediatamente criando tabelas.

Antes disso, precisamos fazer perguntas:

  • Quais informações o sistema precisa armazenar?
  • Quais objetos existem no problema?
  • Quais características desses objetos precisamos guardar?
  • Como esses objetos se relacionam?
  • Quais informações precisam ser únicas?
  • Quais regras o sistema precisa respeitar?
Regra importante:

Não comece pensando em tabelas. Comece pensando no problema e nas informações que precisam ser representadas.

O que são entidades?

Uma entidade representa algo que queremos identificar e armazenar informações sobre dentro do sistema.

No exemplo da loja, podemos identificar entidades como:

👤

Cliente

Pessoa que compra produtos.

📦

Produto

Item vendido pela loja.

🛒

Pedido

Compra realizada por um cliente.

💳

Pagamento

Informação relacionada ao pagamento.

Uma forma de pensar:

Se o sistema precisa guardar informações sobre determinado objeto, pessoa, evento ou conceito, ele pode representar isso como uma entidade.

Entidade e tabela são a mesma coisa?

Não exatamente.

Durante a modelagem, usamos o conceito de entidade para representar algo do domínio do sistema.

Ao implementar um modelo relacional, essa entidade pode ser representada por uma tabela.

Modelo Implementação relacional
Entidade Cliente Tabela clientes
Entidade Produto Tabela produtos
Entidade Pedido Tabela pedidos

O que são atributos?

Atributos são características ou propriedades que descrevem uma entidade.

Por exemplo, um cliente pode possuir:

🆔

ID

Identificador do cliente.

👤

Nome

Nome do cliente.

📧

E-mail

Endereço de e-mail.

📱

Telefone

Telefone do cliente.

Entidade: Cliente

Atributos: ID, nome, e-mail, telefone.

Identificando relacionamentos

Depois de identificar as entidades, precisamos descobrir como elas se relacionam.

No nosso exemplo:

👤 Um cliente realiza 🛒 pedidos.

🛒 Um pedido possui 📦 produtos.

📦 Um produto pode aparecer em vários 🛒 pedidos.

Essas relações fazem parte das regras do sistema e precisam ser representadas no modelo.

O que é cardinalidade?

A cardinalidade ajuda a representar quantas ocorrências de uma entidade podem estar relacionadas a outra entidade.

Alguns exemplos comuns são:

1️⃣

1 : 1

Um registro está relacionado a no máximo um registro do outro lado.

1️⃣➡️👥

1 : N

Um registro pode estar relacionado a vários registros.

👥↔️👥

N : N

Vários registros podem estar relacionados a vários registros.

Esses conceitos serão aprofundados em aulas posteriores.

Exemplo: Cliente e Pedido

Considere a seguinte regra:

Um cliente pode realizar vários pedidos.

Podemos representar isso como:

👤 Cliente

↓

🛒 Pedido

1 : N

Um cliente pode ter muitos pedidos, enquanto cada pedido pertence a um cliente específico.

Exemplo: Pedido e Produto

Agora temos outra situação:

Um pedido pode possuir vários produtos.

Um produto pode aparecer em vários pedidos.

Temos então uma relação:

🛒 Pedido ↔ 📦 Produto

N : N

No modelo relacional, esse tipo de relacionamento normalmente precisa ser representado por uma estrutura intermediária.

Podemos chamá-la, por exemplo, de itens_pedido.

Modelo conceitual

O modelo conceitual representa o problema em um nível mais próximo do negócio e menos preocupado com detalhes técnicos.

Podemos pensar simplesmente em:

👤

Cliente

Realiza pedidos.

🛒

Pedido

Contém itens.

📦

Produto

Pode aparecer em pedidos.

Foco:

Entender o negócio e suas regras antes de pensar nos detalhes do banco.

Modelo lógico

Depois de compreender o problema, podemos começar a definir como os dados serão organizados no modelo escolhido.

No modelo relacional, isso significa começar a definir tabelas, colunas, chaves e relacionamentos.

Tabela Principais colunas
clientes id, nome, email
pedidos id, cliente_id, data
produtos id, nome, preco
itens_pedido pedido_id, produto_id, quantidade

Do modelo para o SQL

Depois de definir o modelo, podemos implementá-lo utilizando SQL.

Por exemplo: 

CREATE TABLE clientes (
    id INTEGER PRIMARY KEY,
    nome VARCHAR(100),
    email VARCHAR(150)
);

O SQL é utilizado aqui para transformar parte do modelo em estruturas que o SGBD pode criar e gerenciar.

O que são regras de negócio?

Durante a modelagem, precisamos entender as regras de negócio do sistema.

Elas representam condições ou comportamentos que fazem parte do funcionamento do negócio.

👤

Cliente

Um cliente pode realizar vários pedidos.

🛒

Pedido

Um pedido pertence a um cliente.

📦

Produto

Um produto pode aparecer em vários pedidos.

Por que isso importa?

O banco de dados precisa representar as regras importantes do sistema. Um modelo mal planejado pode gerar dados duplicados, inconsistências e dificuldades de manutenção.

Erros comuns na modelagem

❌

Colocar tudo em uma tabela

Misturar clientes, produtos e pedidos em uma única estrutura pode gerar repetição e dificuldade de manutenção.

❌

Ignorar relacionamentos

Não representar corretamente as relações pode dificultar consultas e comprometer a consistência.

❌

Não definir identificadores

Sem uma forma adequada de identificar registros, operações sobre os dados ficam mais difíceis.

❌

Modelar sem entender o negócio

Uma estrutura tecnicamente válida pode não representar corretamente as regras do sistema.

Um processo simples de modelagem

1. Entenda o problema

Descubra o que o sistema precisa fazer.

↓

2. Identifique as entidades

Descubra quais objetos e conceitos precisam ser representados.

↓

3. Identifique os atributos

Descubra quais informações precisam ser armazenadas sobre cada entidade.

↓

4. Identifique os relacionamentos

Descubra como as entidades se relacionam.

↓

5. Defina as chaves

Identifique como os registros serão identificados e relacionados.

↓

6. Transforme o modelo em tabelas

No modelo relacional, defina tabelas, colunas e relacionamentos.

Resumindo

🧠 Modelagem de dados é o processo de planejar como as informações serão representadas.

🧩 Entidades representam objetos, pessoas, conceitos ou eventos relevantes para o sistema.

📝 Atributos representam características das entidades.

🔗 Relacionamentos representam como as entidades se conectam.

🔑 Chaves ajudam a identificar e relacionar registros.

📊 No modelo relacional, o modelo pode ser implementado utilizando tabelas.

🔤 Depois disso, podemos utilizar SQL para implementar a estrutura no SGBD.
