📦 O que é Apache Parquet?

Apache Parquet é um formato de arquivo desenvolvido para armazenar dados de maneira eficiente, especialmente em cargas de trabalho analíticas.

Ele é um formato colunar.

Importante:

Parquet não é um banco de dados.

Parquet também não é um SGBD.

Parquet é um formato de armazenamento de dados.

🧩 Banco de dados x Parquet

É importante não confundir os conceitos.

Conceito O que é?
Banco de dados Estrutura organizada para armazenar dados.
SGBD Software que gerencia bancos de dados.
SQL Linguagem utilizada para consultar e manipular dados em bancos relacionais.
Parquet Formato de arquivo colunar para armazenamento eficiente de dados.

📄 Uma alternativa simples: CSV

Uma forma muito conhecida de armazenar dados é o formato CSV. 

id,nome,cidade,idade
1,Ana,Rio de Janeiro,25
2,João,São Paulo,31
3,Maria,Belo Horizonte,28

É simples e possui grande compatibilidade.

Mas será que é a melhor opção para grandes volumes de dados analíticos?

↔️ Armazenamento por linha

Imagine uma tabela: 


ID | Nome  | Cidade          | Idade
-------------------------------------
1  | Ana   | Rio de Janeiro  | 25
2  | João  | São Paulo       | 31
3  | Maria | Belo Horizonte  | 28

Em um armazenamento orientado a linhas, os dados de cada registro ficam agrupados. 

Registro 1
→ 1, Ana, Rio de Janeiro, 25

Registro 2
→ 2, João, São Paulo, 31

Registro 3
→ 3, Maria, Belo Horizonte, 28

⬇️ Armazenamento por coluna

No armazenamento colunar, os valores de uma mesma coluna são agrupados. 

ID:
1
2
3

Maria

Cidade:

Belo Horizonte

Idade:

Essa organização é especialmente interessante para determinados tipos de consultas analíticas.

⚡ Por que Parquet é eficiente?

Uma das principais características do Parquet é seu armazenamento orientado a colunas.

Isso pode ser muito útil quando uma análise precisa acessar apenas algumas colunas de um conjunto de dados muito grande.

Imagine um arquivo com: 

100 milhões de registros

50 colunas

Mas a consulta precisa apenas de: 

cliente_id
valor
data
Em formatos colunares, mecanismos de processamento podem evitar ler dados de colunas que não são necessárias para determinada consulta.

🗜️ Compressão

Outra característica importante do Parquet é sua capacidade de trabalhar bem com compressão.

Como valores semelhantes de uma mesma coluna ficam próximos, determinados algoritmos de compressão podem aproveitar essa organização. 


Cidade:

Rio de Janeiro
Rio de Janeiro
Rio de Janeiro
Rio de Janeiro
São Paulo
São Paulo
São Paulo
...

Dados com padrões semelhantes podem apresentar boas oportunidades de compressão.

Menos dados armazenados também significa, em muitos cenários, menos dados para movimentar e processar.

🧬 Schema

Arquivos Parquet armazenam informações sobre a estrutura e os tipos dos dados.

Por exemplo: 

id       → inteiro

nome     → texto

preco    → decimal

ativo    → boolean

data     → timestamp

Essas informações ajudam ferramentas de processamento a interpretar os dados corretamente.

🧱 Tipos de dados

Diferentemente de um CSV puramente textual, Parquet possui suporte a tipos de dados.

Campo Tipo Exemplo

Característica CSV Parquet

🏞️ Parquet e Data Lake

Parquet é frequentemente encontrado em arquiteturas de Data Lake.

Um Data Lake pode armazenar grandes quantidades de dados em diferentes formatos. 


                    DATA LAKE
                       │
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
      CSV           JSON          PARQUET
        │              │              │
        └──────────────┼──────────────┘
                       ↓
                 PROCESSAMENTO
                       │
                       ↓
                  ANALYTICS

🏢 Data Lake x Data Warehouse

É importante não confundir esses conceitos.

Data Lake Data Warehouse
Pode armazenar dados em diferentes formatos. Normalmente possui dados estruturados para análise.
Pode armazenar dados brutos. Dados geralmente preparados para análise.
Pode utilizar arquivos Parquet. Pode utilizar diferentes tecnologias de armazenamento.

🛠️ Quem trabalha com Parquet?

Parquet não funciona sozinho como um banco de dados. Ele normalmente é utilizado por ferramentas de processamento e análise.

⚡ Apache Spark

Processamento distribuído de grandes volumes de dados.

🦆 DuckDB

Banco analítico que consegue consultar arquivos como Parquet diretamente.

☁️ Data Lake

Armazenamento de grandes volumes de dados em ambientes distribuídos.

📊 Ferramentas analíticas

Diversas ferramentas modernas conseguem ler e processar arquivos Parquet.

🐍 Parquet com Python

Uma forma comum de trabalhar com arquivos Parquet é utilizando bibliotecas de análise de dados.

Por exemplo, utilizando pandas: 

import pandas as pd

df = pd.read_parquet("vendas.parquet")

print(df.head())

Também podemos salvar um DataFrame como Parquet: 

df.to_parquet(
    "vendas.parquet"
)

❌ Parquet não substitui um banco de dados

É importante entender que Parquet não foi criado para substituir todos os bancos de dados.

Por exemplo, uma aplicação web precisa frequentemente realizar operações como: 

INSERT
UPDATE
DELETE

em dados que estão sendo modificados constantemente.

Para esse tipo de cenário, um banco de dados pode ser mais apropriado.

Parquet é especialmente interessante como formato de armazenamento e intercâmbio para cargas analíticas, não como substituto universal de um SGBD.

🔄 OLTP x OLAP

Essa diferença nos leva a dois tipos importantes de cargas de trabalho.

OLTP OLAP
Sistemas transacionais Análise de dados
Muitas operações pequenas Consultas analíticas
Aplicações do dia a dia Relatórios e dashboards
Exemplo: sistema de pedidos Exemplo: análise de vendas

Parquet aparece principalmente no contexto de processamento analítico.

Nesse cenário, o banco operacional pode armazenar os dados utilizados pela aplicação enquanto os dados históricos são preparados para análise.

📝 Resumindo

Parquet é um formato de arquivo orientado a colunas.

Ele é especialmente útil para armazenamento e processamento analítico de grandes volumes de dados.

Parquet não é um banco de dados e não é um SGBD.

Seu formato colunar permite que ferramentas processem somente as colunas necessárias para determinadas consultas.

Compressão e metadados de tipos também contribuem para sua eficiência.

É comum encontrar Parquet em Data Lakes, pipelines de dados e ambientes de Big Data.
