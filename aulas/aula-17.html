🍃 O que é MongoDB?

MongoDB é um SGBD NoSQL orientado a documentos.

Diferentemente de um banco de dados relacional, que normalmente organiza os dados em tabelas, o MongoDB trabalha principalmente com documentos agrupados em coleções.

Uma distinção importante:

MongoDB é o SGBD.

Dentro dele podemos criar e gerenciar bancos de dados.

Esses bancos podem conter coleções, que armazenam documentos.

🗂️ Como os conceitos se organizam?

Podemos imaginar a estrutura básica do MongoDB desta maneira: 

MongoDB
   │
   ├── Banco de dados
   │       │
   │       ├── Coleção
   │       │      ├── Documento
   │       │      ├── Documento
   │       │      └── Documento
   │       │
   │       └── Coleção
   │              ├── Documento
   │              └── Documento
   │
   └── Outro banco de dados

SGBD

MongoDB gerencia os bancos e fornece os recursos para trabalhar com os dados.

Banco de dados

Ambiente onde as coleções são organizadas.

Coleção

Grupo de documentos relacionados.

Documento

Estrutura que representa uma informação.

🔄 MongoDB × Banco relacional

Uma maneira simples de começar a entender MongoDB é comparar alguns conceitos com aquilo que já aprendemos em SQL.

Relacional MongoDB
Banco de dados Database
Tabela Coleção
Linha / registro Documento
Coluna Campo
JOIN Existem diferentes formas de trabalhar com dados relacionados, dependendo do caso.
Atenção:

Essa tabela é uma aproximação para facilitar o aprendizado.

Uma coleção não é simplesmente uma "tabela diferente", e um documento não é exatamente equivalente a uma linha de uma tabela.

📄 O que é um documento?

Um documento MongoDB representa um conjunto de campos e valores. 

{
    "_id": "...",
    "nome": "Ana Silva",
    "email": "ana@email.com",
    "idade": 25
}

Nesse exemplo temos quatro campos:

  • _id
  • nome
  • email
  • idade

Cada campo possui um valor associado.

🧩 JSON e BSON

Ao trabalhar com MongoDB, você verá frequentemente estruturas semelhantes ao JSON. 

{
    "nome": "Ana",
    "idade": 25,
    "ativo": true
}

Internamente, o MongoDB utiliza BSON, que significa Binary JSON.

Resumo:

JSON é uma representação textual muito utilizada para visualizar e trocar dados.

BSON é o formato binário utilizado pelo MongoDB para representar documentos internamente.

🔢 Tipos de dados

Documentos MongoDB podem armazenar diferentes tipos de valores.

Tipo Exemplo
String "Ana"
Número 25
Boolean true
Array ["SQL", "NoSQL"]
Objeto { cidade: "Rio" }
Data Date
ObjectId Identificador utilizado frequentemente pelo MongoDB.

🆔 O campo _id

Um conceito muito importante no MongoDB é o campo _id.

Cada documento de uma coleção possui um identificador único. 

{
    "_id": ObjectId("65a123..."),
    "nome": "Ana Silva"
}

Quando não fornecemos um valor para _id, o MongoDB normalmente gera automaticamente um ObjectId.

Por que isso é importante?

O identificador permite distinguir um documento dos demais dentro de uma coleção.

🗃️ O que é uma coleção?

Uma coleção é um agrupamento de documentos relacionados.

Podemos imaginar um banco de dados de uma loja: 

loja
│
├── clientes
│      ├── documento
│      ├── documento
│      └── documento
│
├── produtos
│      ├── documento
│      ├── documento
│      └── documento
│
└── pedidos
       ├── documento
       └── documento

Nesse exemplo, temos três coleções:

  • clientes
  • produtos
  • pedidos

🛒 Exemplo: loja virtual

Imagine que queremos armazenar um cliente. 

{
    "nome": "Carlos Souza",
    "email": "carlos@email.com",
    "idade": 32,
    "cidade": "São Paulo"
}

Esse documento poderia estar dentro da coleção clientes.

Outro cliente poderia ser representado por outro documento: 

{
    "nome": "Mariana Oliveira",
    "email": "mariana@email.com",
    "idade": 28,
    "cidade": "Belo Horizonte"
}
Perceba:

Os documentos possuem uma estrutura semelhante, mas o MongoDB permite trabalhar com estruturas que podem variar conforme o modelo e as regras definidas para a aplicação.

📦 Documentos podem conter outros dados

Uma característica importante do modelo documental é a possibilidade de representar estruturas aninhadas. 

{
    "nome": "Ana Silva",

    "endereco": {

        "rua": "Rua das Flores",

        "numero": 100,

        "cidade": "Rio de Janeiro"

    }
}

O campo endereco contém outro objeto com seus próprios campos.

Isso permite representar estruturas que seriam modeladas de outra maneira em um banco relacional.

📚 Arrays dentro dos documentos

Também podemos armazenar listas dentro de um documento. 

{
    "nome": "Ana",

    "interesses": [

        "Banco de Dados",

        "Programação",

        "Tecnologia"

    ]
}

Nesse exemplo, interesses é um array contendo três valores.

Essa é uma das ideias centrais do modelo documental:

Dados relacionados podem, em determinados casos, ser representados juntos no mesmo documento.

💻 Conhecendo o Mongo Shell

Para interagir com o MongoDB podemos utilizar ferramentas de linha de comando, como o mongosh.

Depois de conectar ao servidor MongoDB, podemos selecionar um banco de dados: 

use loja

Podemos verificar o banco atualmente selecionado: 

db

E podemos listar as coleções existentes: 

show collections
Importante:

Esses comandos serão utilizados apenas para introduzir o ambiente.

Na próxima aula vamos começar a criar e consultar documentos de maneira mais detalhada.

✍️ Inserindo um documento

Uma das operações mais básicas do MongoDB é inserir um documento em uma coleção. 

db.clientes.insertOne({

    nome: "Ana Silva",

    email: "ana@email.com",

    idade: 25

})

Nesse exemplo:

  • db representa o banco selecionado.
  • clientes representa a coleção.
  • insertOne() solicita a inserção de um documento.
  • O objeto contém os dados que serão armazenados.
Não precisa decorar agora.

O objetivo desta aula é reconhecer a estrutura. As operações CRUD serão estudadas com mais profundidade nas próximas aulas.

🔎 Consultando documentos

Também podemos solicitar documentos de uma coleção. 

db.clientes.find()

Esse comando solicita os documentos existentes na coleção clientes.

Podemos pensar inicialmente em uma comparação conceitual: 

SQL:

SELECT *
FROM clientes;


MongoDB:

db.clientes.find()
Importante:

As duas operações possuem objetivos semelhantes, mas SQL e a linguagem de consulta do MongoDB possuem sintaxes e modelos diferentes.

🧠 O que aprendemos?

MongoDB

É um SGBD NoSQL orientado a documentos.

Database

É o banco de dados onde as coleções são organizadas.

Collection

Agrupa documentos relacionados.

Document

Armazena campos e valores.

⚠️ Erros comuns

❌ "MongoDB é um banco de dados"

Tecnicamente, MongoDB é um SGBD que gerencia bancos de dados.

❌ "Coleção é exatamente uma tabela"

A comparação ajuda no início, mas os modelos possuem diferenças importantes.

❌ "Documento é exatamente uma linha"

Um documento pode conter estruturas aninhadas e arrays.

❌ "JSON e BSON são a mesma coisa"

São formatos relacionados, mas possuem características diferentes.
