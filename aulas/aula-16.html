O que significa NoSQL?

NoSQL é um termo utilizado para descrever uma variedade de sistemas de gerenciamento de bancos de dados que não seguem necessariamente o modelo relacional tradicional.

NoSQL não significa simplesmente "sem SQL".

O termo é frequentemente associado à ideia de Not Only SQL, destacando que existem outras formas de modelar e consultar dados além do modelo relacional tradicional.

Portanto, NoSQL não representa um único banco de dados. É uma categoria que reúne diferentes modelos de armazenamento.

🗄️ Relembrando o modelo relacional

Antes de entender NoSQL, precisamos lembrar como funciona o modelo que estudamos no módulo anterior. 

clientes

┌────┬──────────────┬──────────────────────┐
│ id │ nome         │ email                │
├────┼──────────────┼──────────────────────┤
│ 1  │ Ana Silva    │ ana@email.com        │
│ 2  │ João Santos  │ joao@email.com       │
└────┴──────────────┴──────────────────────┘

No modelo relacional, os dados são organizados principalmente em tabelas.

Essas tabelas podem possuir relacionamentos por meio de chaves primárias e estrangeiras.

Modelo mental:

Tabelas → linhas → colunas → relacionamentos

📄 E se os dados fossem armazenados como documentos?

Em alguns bancos NoSQL, podemos representar os dados utilizando documentos. 

{
    "id": 1,
    "nome": "Ana Silva",
    "email": "ana@email.com",
    "cidade": "Rio de Janeiro"
}

Perceba que agora não estamos olhando para uma tabela com linhas e colunas.

Estamos trabalhando com uma estrutura semelhante a um documento.

Novo modelo mental:

Documento → campos → valores

Por que NoSQL ganhou espaço?

Com a evolução das aplicações, surgiram sistemas que precisavam lidar com grandes volumes de dados, diferentes formatos de informação e cargas de acesso distribuídas.

Em determinados cenários, modelos não relacionais podem oferecer características interessantes para a arquitetura da aplicação.

📈

Grande volume

Aplicações podem trabalhar com grandes quantidades de dados.

🌎

Distribuição

Sistemas podem ser distribuídos entre diferentes servidores e regiões.

🧩

Dados variados

Nem todas as informações precisam seguir exatamente a mesma estrutura.

⚡

Padrões de acesso

Alguns sistemas são projetados para determinados padrões de leitura e escrita.

Importante:

Isso não significa que NoSQL seja automaticamente mais rápido ou melhor que SQL.

A escolha depende do problema, dos dados, dos requisitos da aplicação e da tecnologia utilizada.

NoSQL substitui SQL?

Não existe uma regra dizendo que uma aplicação deve utilizar necessariamente SQL ou NoSQL.

Cada modelo possui características diferentes.

Modelo relacional Modelos NoSQL
Dados organizados principalmente em tabelas. Dados podem ser organizados em documentos, chave-valor, grafos ou colunas largas.
Relacionamentos são parte importante do modelo. Alguns modelos priorizam estruturas e padrões de acesso diferentes.
SQL é utilizado para consultas relacionais. A forma de consulta depende do SGBD e do modelo utilizado.
Schema geralmente definido de forma estruturada. Alguns modelos permitem estruturas mais flexíveis.

Os principais modelos NoSQL

NoSQL não é um único modelo. Existem diferentes formas de organizar os dados.

DOCUMENTOS

📄 Document Store

Armazena dados em documentos. É o modelo utilizado pelo MongoDB.

CHAVE-VALOR

🔑 Key-Value

Os dados são armazenados como pares de chave e valor.

COLUNAS LARGAS

🧱 Wide-Column

Organiza dados em estruturas orientadas a famílias de colunas.

GRAFOS

🕸️ Graph

Representa entidades e seus relacionamentos como nós e arestas.

1. Banco orientado a documentos

Bancos orientados a documentos armazenam informações em documentos estruturados. 

{
    "nome": "Ana",
    "email": "ana@email.com",
    "idade": 25,
    "enderecos": [
        {
            "cidade": "Rio de Janeiro",
            "cep": "20000-000"
        }
    ]
}

Observe que podemos representar informações relacionadas dentro do próprio documento.

Exemplo:

MongoDB é um banco de dados orientado a documentos.

2. Banco chave-valor

Nesse modelo, cada informação é associada a uma chave. 

usuario:1001 → "Ana"

usuario:1002 → "João"

usuario:1003 → "Maria"

Também podemos armazenar estruturas mais complexas como valores. 

sessao:abc123 → {
    usuario: 1001,
    login: "2026-01-15",
    ativo: true
}
Exemplo:

Redis é amplamente conhecido por seu modelo baseado em estruturas chave-valor, embora também ofereça outras estruturas de dados.

3. Banco orientado a colunas largas

Bancos wide-column organizam dados utilizando estruturas orientadas a famílias de colunas.

Esse modelo é utilizado em determinados sistemas distribuídos que precisam trabalhar com grandes volumes de dados.

Apache Cassandra

Banco distribuído orientado a colunas largas.

HBase

Banco distribuído inspirado no modelo Bigtable.

4. Banco de grafos

Bancos de grafos são projetados para representar entidades e seus relacionamentos.

O que acontece com o schema?

Uma diferença frequentemente associada aos bancos NoSQL é a possibilidade de trabalhar com estruturas de dados mais flexíveis em determinados modelos.

Por exemplo, podemos imaginar dois documentos: 

{
    "nome": "Ana",
    "email": "ana@email.com"
}


{
    "nome": "João",
    "email": "joao@email.com",
    "telefone": "99999-9999"
}

Dependendo do banco e da configuração utilizada, estruturas diferentes podem ser armazenadas.

Mas cuidado:

"Schema flexível" não significa "sem estrutura".

A aplicação ainda precisa definir regras, validações e expectativas sobre os dados.

📈 Escalabilidade

Um dos conceitos importantes quando estudamos sistemas distribuídos é a escalabilidade.

Escalabilidade vertical

Aumentar os recursos de uma máquina existente, como CPU, memória ou armazenamento.

Escalabilidade horizontal

Adicionar mais máquinas ao sistema. 

        ┌─────────────┐
        │   Servidor  │
        │      1      │
        └─────────────┘
              │
        ┌─────┴─────┐
        │           │
┌─────────────┐ ┌─────────────┐
│   Servidor  │ │   Servidor  │
│      2      │ │      3      │

Muitos sistemas NoSQL foram projetados pensando em ambientes distribuídos e escalabilidade horizontal.

Isso não significa que todo banco NoSQL necessariamente será distribuído ou que bancos relacionais não possam ser escalados horizontalmente.

Consistência, disponibilidade e distribuição

Ao estudar sistemas distribuídos, começamos a encontrar conceitos diferentes daqueles mais comuns no início do estudo de SQL.

Consistência

Diferentes componentes do sistema observam os dados de acordo com as garantias definidas pelo sistema.

Disponibilidade

O sistema continua capaz de responder às operações dentro das condições previstas.

Particionamento

O sistema precisa lidar com falhas ou interrupções de comunicação entre partes distribuídas.

Esses conceitos serão aprofundados posteriormente, especialmente quando estudarmos bancos distribuídos.

🧠 Não confunda banco de dados com SGBD

Assim como fizemos no módulo SQL, precisamos manter a distinção entre os conceitos.

Banco de dados

É o conjunto de dados armazenados e organizados de acordo com o modelo utilizado.

SGBD

É o software responsável por gerenciar o banco de dados.

Aplicação

É o software que utiliza o SGBD para realizar operações sobre os dados.

Exemplo:

MongoDB é um SGBD orientado a documentos.

Dentro dele podem existir bancos de dados, coleções e documentos.

Uma aplicação pode utilizar o MongoDB para armazenar e consultar essas informações.

SQL × NoSQL

Conceito SQL NoSQL
Modelo Relacional Pode ser documento, chave-valor, grafo, wide-column etc.
Estrutura Tabelas Depende do modelo
Relacionamentos Parte fundamental do modelo Depende do modelo e do banco
Linguagem SQL Depende do SGBD
Schema Geralmente estruturado Pode ser mais flexível, dependendo do banco

⚠️ Erros comuns sobre NoSQL

❌ "NoSQL não usa estrutura"

Todo banco precisa possuir alguma forma de organização dos dados.

❌ "NoSQL é sempre mais rápido"

Performance depende do modelo, da consulta, dos dados e da arquitetura.

❌ "NoSQL substitui SQL"

São abordagens diferentes para diferentes necessidades.

❌ "NoSQL significa MongoDB"

MongoDB é apenas um dos SGBDs que pertence ao universo NoSQL.

📝 Resumindo

NoSQL é uma categoria de sistemas de banco de dados que inclui diferentes modelos além do relacional tradicional.

Os principais modelos estudados foram documentos, chave-valor, wide-column e grafos.

Bancos NoSQL podem ser utilizados em diferentes cenários, especialmente quando suas características combinam com os requisitos da aplicação.

NoSQL não significa necessariamente "sem estrutura", "sem SQL" ou "mais rápido".

A escolha entre SQL e NoSQL depende do problema, do modelo de dados, dos padrões de acesso e dos requisitos do sistema.
