🪟 O que é uma Window Function?

Uma Window Function permite realizar cálculos considerando um conjunto de linhas relacionadas à linha atual.

A grande diferença para o GROUP BY é que uma Window Function normalmente não reduz o número de linhas do resultado.

GROUP BY Window Function
Agrupa várias linhas em uma linha de resultado. Mantém as linhas e calcula informações considerando outras linhas.
Muito utilizado para agregações. Muito utilizado para análises comparativas.

🧩 Estrutura de uma Window Function

Uma Window Function utiliza a cláusula OVER(). 

SELECT

    produto,

    preco,

    AVG(preco)
        OVER() AS media_geral

FROM 'vendas.parquet';

A consulta calcula a média geral, mas mantém cada registro individual no resultado.

🔢 ROW_NUMBER

ROW_NUMBER() atribui um número sequencial para cada linha. 

SELECT

    produto,

    preco,

    ROW_NUMBER()
        OVER(
            ORDER BY preco DESC
        ) AS posicao

FROM 'vendas.parquet';

Agora cada produto recebe uma posição baseada no preço.

🏆 RANK

O RANK() também cria uma classificação, mas trata valores iguais de maneira diferente. 

SELECT

    produto,

    preco,

    RANK()
        OVER(
            ORDER BY preco DESC
        ) AS ranking

FROM 'vendas.parquet';
ROW_NUMBER x RANK

ROW_NUMBER cria uma sequência única.

RANK permite que registros tenham a mesma posição quando possuem valores iguais.

📦 PARTITION BY

O PARTITION BY permite criar grupos dentro da Window Function.

Imagine que queremos criar um ranking de produtos separado para cada categoria. 

SELECT

    categoria,

    produto,

    preco,

    RANK()
        OVER(

            PARTITION BY categoria

            ORDER BY preco DESC

        ) AS ranking

FROM 'vendas.parquet';

Agora o ranking começa novamente dentro de cada categoria.

📈 SUM com Window Function

Também podemos utilizar funções de agregação como SUM() dentro de uma janela. 

SELECT

    data,

    quantidade * preco AS valor,

    SUM(quantidade * preco)
        OVER(
            ORDER BY data
        ) AS faturamento_acumulado

FROM 'vendas.parquet'

ORDER BY
    data;

Isso cria um faturamento acumulado ao longo do tempo.

📊 Acumulado por categoria

Podemos combinar PARTITION BY com SUM(). 

SELECT

    categoria,

    data,

    quantidade * preco AS valor,

    SUM(quantidade * preco)
        OVER(

            PARTITION BY categoria

            ORDER BY data

        ) AS acumulado_categoria

FROM 'vendas.parquet';

Cada categoria possui seu próprio acumulado.

⬅️ LAG

A função LAG() permite acessar o valor de uma linha anterior. 

SELECT

    data,

    faturamento,

    LAG(faturamento)
        OVER(
            ORDER BY data
        ) AS faturamento_anterior

FROM vendas_diarias;

Isso permite comparar um período com o período anterior.

📈 Calculando crescimento

Com LAG podemos calcular a variação entre períodos. 

SELECT

    data,

    faturamento,

    LAG(faturamento)
        OVER(
            ORDER BY data
        ) AS faturamento_anterior,

    faturamento -
        LAG(faturamento)
        OVER(
            ORDER BY data
        ) AS variacao

FROM vendas_diarias;

Esse tipo de cálculo é muito utilizado em análises temporais.

➡️ LEAD

O LEAD() faz o oposto do LAG: permite acessar uma linha posterior. 

SELECT

    data,

    faturamento,

    LEAD(faturamento)
        OVER(
            ORDER BY data
        ) AS proximo_faturamento

FROM vendas_diarias;

🪟 Window Frame

Podemos controlar exatamente quais linhas participam do cálculo utilizando um Window Frame.

Por exemplo, podemos calcular uma média móvel. 

SELECT

    data,

    faturamento,

    AVG(faturamento)
        OVER(

            ORDER BY data

            ROWS BETWEEN
                6 PRECEDING
                AND CURRENT ROW

        ) AS media_movel_7_dias

FROM vendas_diarias;

Nesse exemplo estamos calculando uma média móvel considerando uma janela de até sete registros.

🧠 Principais Window Functions

Função Utilização
ROW_NUMBER() Numeração sequencial.
RANK() Ranking permitindo empates.
SUM() OVER Totais e acumulados.
AVG() OVER Médias e médias móveis.
LAG() Acessar valores anteriores.
LEAD() Acessar valores posteriores.

🔄 SQL e NoSQL: onde chegamos?

Durante o curso trabalhamos com diferentes formas de armazenamento e processamento de dados.

Tecnologia Conceito
SQL Linguagem para consultar e manipular dados em bancos que suportam SQL.
NoSQL Família de modelos de bancos de dados que não dependem do modelo relacional tradicional.
MongoDB SGBD orientado a documentos.
Parquet Formato de armazenamento colunar voltado especialmente para dados analíticos.
DuckDB SGBD analítico que permite executar SQL diretamente sobre arquivos e outras fontes.

🧠 Uma distinção importante

SQL é uma linguagem.

NoSQL é uma categoria de abordagens e modelos de bancos de dados.

MongoDB é um SGBD orientado a documentos.

Parquet é um formato de arquivo colunar para armazenamento de dados.

DuckDB é um SGBD analítico que pode consultar arquivos como Parquet.
