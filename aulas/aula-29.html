Transações e Consistência no MongoDB

Aprenda como executar várias operações como uma única unidade de trabalho e como utilizar transações para manter os dados consistentes.

🎯 Objetivos da aula

Em aplicações reais, algumas operações precisam acontecer juntas. Se uma parte da operação falhar, pode ser necessário desfazer as alterações realizadas anteriormente.

Nesta aula vamos entender como o MongoDB trabalha com transações.

💡 Por que precisamos de transações?

Imagine uma aplicação bancária.

O usuário possui: 

Conta A
Saldo: R$ 1.000,00

Conta B
Saldo: R$ 500,00

Agora imagine uma transferência de: 

R$ 200,00

Essa operação envolve pelo menos duas alterações:

  1. Retirar R$ 200 da Conta A.
  2. Adicionar R$ 200 à Conta B.
E se a primeira operação funcionar e a segunda falhar?

A Conta A ficaria com R$ 800, mas a Conta B continuaria com R$ 500.

O dinheiro teria desaparecido do sistema.

É justamente para situações desse tipo que as transações são importantes.

🔄 O que é uma transação?

Uma transação é um conjunto de operações tratado como uma única unidade de trabalho.

A ideia principal é:

Todas as operações devem ser confirmadas juntas ou as alterações da transação devem ser descartadas.

Podemos representar uma transferência assim: 

INÍCIO DA TRANSAÇÃO

    ↓

Debitar Conta A

    ↓

Creditar Conta B

    ↓

CONFIRMAR

    ↓

FIM

Se alguma etapa apresentar um erro, podemos cancelar a transação.

⚛️ Atomicidade

Um dos conceitos mais importantes relacionados a transações é a atomicidade.

Atomicidade significa que uma transação deve ser tratada como uma unidade indivisível.

✅

Sucesso

As operações são confirmadas.

❌

Falha

As alterações da transação podem ser descartadas.

Pense em uma transação como um pacote de operações: 

┌──────────────────────────┐
│       TRANSAÇÃO          │
│                          │
│  Operação 1              │
│  Operação 2              │
│  Operação 3              │
│                          │
└──────────────────────────┘

        ↓

   COMMIT ou ABORT

🧠 ACID

Transações são frequentemente explicadas através das propriedades conhecidas como ACID.

Letra Conceito Ideia
A Atomicidade A transação é tratada como uma unidade.
C Consistência A transação deve preservar as regras de consistência dos dados.
I Isolamento Operações de transações concorrentes possuem regras de isolamento.
D Durabilidade Após a confirmação, os dados devem permanecer persistidos conforme as garantias do sistema.

🧵 O que é uma sessão?

Para trabalhar com uma transação no MongoDB, utilizamos uma sessão.

A sessão representa o contexto no qual as operações relacionadas à transação serão executadas.

Conceitualmente: 

Sessão

    ↓

Iniciar transação

    ↓

Executar operações

    ↓

Commit ou Abort

    ↓

Encerrar sessão

▶️ Iniciando uma transação

Em aplicações que utilizam o driver do MongoDB, uma transação é iniciada através de uma sessão.

Um exemplo conceitual utilizando JavaScript com o driver do MongoDB: 

const session = client.startSession();

session.startTransaction();

A partir desse momento, as operações relacionadas à transação podem utilizar essa sessão.

💳 Exemplo: transferência bancária

Imagine duas contas: 

Conta A

{
    numero: 1001,
    saldo: 1000
}


Conta B

{
    numero: 1002,
    saldo: 500
}

Queremos transferir R$ 200. 

Conta A
1000 → 800

Conta B
500 → 700

As duas alterações devem fazer parte da mesma transação.

💻 Exemplo de transação

Um exemplo simplificado utilizando o driver oficial do MongoDB para Node.js: 

const session = client.startSession();

try {

    session.startTransaction();

    await contas.updateOne(
        { numero: 1001 },
        { $inc: { saldo: -200 } },
        { session }
    );

    await contas.updateOne(
        { numero: 1002 },
        { $inc: { saldo: 200 } },
        { session }
    );

    await session.commitTransaction();

} catch (erro) {

    await session.abortTransaction();

    throw erro;

} finally {

    await session.endSession();

}

Observe a sequência:

  1. Criamos uma sessão.
  2. Iniciamos a transação.
  3. Executamos as operações utilizando a sessão.
  4. Confirmamos com commitTransaction().
  5. Em caso de erro, utilizamos abortTransaction().
  6. Encerramos a sessão.

✅ commitTransaction()

O método: 

session.commitTransaction();

é utilizado para confirmar a transação.

Depois do commit, as alterações da transação são confirmadas de acordo com as garantias configuradas para a operação.

Commit = confirmar a transação.

↩️ abortTransaction()

Quando precisamos cancelar a transação, utilizamos: 

session.abortTransaction();

Isso descarta as alterações realizadas dentro da transação que ainda não foram confirmadas.

Abort = cancelar a transação.

⚖️ Commit x Abort

Comando Função Quando usar
commitTransaction() Confirma a transação. Quando todas as operações foram concluídas corretamente.
abortTransaction() Cancela a transação. Quando ocorre uma falha ou a operação precisa ser cancelada.

⚠️ O que pode acontecer sem uma transação?

Imagine: 

1. Debitar Conta A
        ↓
2. Erro inesperado
        ↓
3. Creditar Conta B

Se a segunda operação nunca acontecer, o sistema pode ficar em um estado que não representa a operação desejada.

A necessidade de uma transação depende do domínio e das regras da aplicação.

Nem toda sequência de operações precisa estar dentro de uma transação.

📄 Uma única operação já pode ser atômica

É importante não concluir que toda operação no MongoDB precisa de uma transação.

Uma operação que modifica um único documento possui garantias de atomicidade nesse nível.

Por exemplo: 

db.contas.updateOne(

    { numero: 1001 },

    {
        $inc: {
            saldo: -200
        }
    }

)

Muitas operações podem ser modeladas para aproveitar a atomicidade de um único documento, evitando uma transação quando ela não é necessária.

🤔 Quando utilizar uma transação?

Transações são úteis quando várias operações precisam ser tratadas como uma única unidade lógica.

  • Transferências entre contas.
  • Operações que alteram múltiplos documentos relacionados.
  • Processos que precisam confirmar várias alterações juntas.
  • Operações em que uma falha parcial deixaria os dados em um estado indesejado.

⚠️ Transações não devem ser usadas automaticamente

Embora transações sejam importantes, elas não devem ser adicionadas a todas as operações sem necessidade.

Antes de utilizar uma transação, vale perguntar:

1️⃣ Preciso alterar vários dados?

Talvez uma transação seja necessária.

2️⃣ Existe uma dependência entre operações?

Se uma operação depende da outra, analise a necessidade de transação.

3️⃣ Um único documento resolve?

Talvez seja possível modelar o documento para evitar uma transação.

🧩 Consistência

Consistência significa que uma transação deve respeitar as regras e restrições definidas para os dados.

Imagine que uma aplicação possui a regra: 

saldo >= 0

A aplicação precisa garantir que suas operações respeitem essa regra.

O banco fornece mecanismos de consistência, mas as regras de negócio continuam sendo responsabilidade da aplicação.

🔒 Isolamento

Aplicações podem possuir vários usuários realizando operações simultaneamente.

Por exemplo: 

Usuário A
      ↓
Atualiza pedido

Usuário B
      ↓
Atualiza o mesmo pedido

Usuário C
      ↓
Consulta o pedido

O banco precisa controlar como essas operações concorrentes interagem.

Esse é um dos motivos pelos quais o conceito de isolamento é importante em transações.

💾 Durabilidade

Depois que uma transação é confirmada, existe uma expectativa de que as alterações persistam de acordo com as garantias de durabilidade configuradas.

Esse conceito é representado pela letra D de ACID.

Commit não significa simplesmente "apertei salvar".

A durabilidade depende das configurações e garantias de escrita e replicação utilizadas pelo ambiente.

🛒 Exemplo: pedido em uma loja virtual

Imagine que um cliente finalize uma compra.

A aplicação precisa:

  1. Criar o pedido.
  2. Registrar os itens do pedido.
  3. Atualizar o estoque.
  4. Registrar informações relacionadas ao pagamento.

Dependendo da modelagem e das regras do sistema, algumas dessas operações podem precisar ser tratadas conjuntamente.

A modelagem deve ser analisada antes de decidir que tudo precisa estar em uma única transação.

✅ Boas práticas

  • Mantenha transações tão curtas quanto possível.
  • Evite colocar operações desnecessárias dentro de uma transação.
  • Planeje a modelagem antes de depender de transações para tudo.
  • Trate erros corretamente.
  • Garanta que as operações pertencentes à transação utilizem a sessão correta.
  • Teste cenários de falha.

📝 Resumindo

Uma transação agrupa operações que devem ser tratadas como uma unidade lógica.

commitTransaction() confirma a transação.

abortTransaction() cancela a transação.

As propriedades ACID ajudam a compreender as garantias associadas às transações.

Uma operação envolvendo um único documento pode muitas vezes aproveitar as garantias de atomicidade do próprio documento, sem exigir uma transação multi-documento.

Transações devem ser utilizadas quando fazem sentido para as regras e para a modelagem da aplicação.
