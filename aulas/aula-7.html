AULA 7 • RELACIONAMENTOS E JOIN

Relacionamentos entre tabelas e JOIN

Aprenda como tabelas se relacionam por meio de chaves e como utilizar JOIN para consultar informações relacionadas.

Objetivos da aula

Em um banco de dados relacional, as informações normalmente são distribuídas entre diferentes tabelas.

Nesta aula vamos aprender como essas tabelas podem se relacionar e como recuperar informações de várias tabelas utilizando JOIN.

Por que precisamos relacionar tabelas?

Imagine uma loja virtual.

Podemos ter uma tabela para armazenar clientes e outra para armazenar pedidos.

ID Nome E-mail
1 Ana ana@email.com
2 João joao@email.com
3 Maria maria@email.com

Essa poderia ser a tabela clientes.

ID Cliente ID Data Total
101 1 2026-01-10 350.00
102 1 2026-01-15 120.00
103 2 2026-01-20 500.00

Essa poderia ser a tabela pedidos.

Observe:

O campo cliente_id da tabela pedidos indica a qual cliente aquele pedido pertence.

O que é uma chave primária?

Uma chave primária, ou Primary Key (PK), é uma coluna ou conjunto de colunas utilizada para identificar unicamente cada registro de uma tabela.

Por exemplo: 

CREATE TABLE clientes (

    id INT PRIMARY KEY,

    nome VARCHAR(100),

    email VARCHAR(150)

);

Nesse exemplo, o campo id é a chave primária.

Identificação

Cada registro possui uma identificação única.

Não deve se repetir

Dois registros não podem possuir a mesma chave primária.

Não deve ser NULL

Uma chave primária precisa identificar o registro.

O que é uma chave estrangeira?

Uma chave estrangeira, ou Foreign Key (FK), é uma coluna utilizada para fazer referência a uma chave de outra tabela.

Por exemplo, podemos criar a tabela pedidos: 

CREATE TABLE pedidos (

    id INT PRIMARY KEY,

    cliente_id INT,

    data_pedido DATE,

    total DECIMAL(10,2),

    FOREIGN KEY (cliente_id)
        REFERENCES clientes(id)

);

Aqui temos:

  • clientes.id → chave primária.
  • pedidos.cliente_id → chave estrangeira.
  • pedidos.cliente_id referencia clientes.id.
Em termos simples:

A chave estrangeira permite dizer: "este registro está relacionado àquele registro da outra tabela".

Relacionamento 1:N

Um dos relacionamentos mais comuns em bancos relacionais é o relacionamento um para muitos (1:N).

No nosso exemplo:

1 cliente → pode possuir muitos pedidos.

1 pedido → pertence a 1 cliente. 

CLIENTES
   │
   │ 1
   │
   │
   │ N
   ▼
PEDIDOS

A chave estrangeira normalmente fica no lado "muitos".

Portanto: 

clientes
    id
     │
     │
     ▼
pedidos
    cliente_id

O que é JOIN?

O JOIN permite combinar registros de duas ou mais tabelas com base em uma condição de relacionamento.

Por exemplo, queremos descobrir o nome do cliente de cada pedido.

Temos:

clientes pedidos
id = 1
Ana 		cliente_id = 1
total = 350
id = 2
João 		cliente_id = 2
total = 500

Podemos relacionar: 

clientes.id = pedidos.cliente_id

Utilizando INNER JOIN: 

SELECT
    clientes.nome,
    pedidos.id,
    pedidos.total

FROM clientes

INNER JOIN pedidos
    ON clientes.id = pedidos.cliente_id;

O resultado poderá ser:

Nome Pedido Total
Ana 101 350.00
Ana 102 120.00
João 103 500.00

Como ler um JOIN?

Observe novamente: 

SELECT
    clientes.nome,
    pedidos.total

FROM clientes

INNER JOIN pedidos
    ON clientes.id = pedidos.cliente_id;

Podemos interpretar a consulta da seguinte maneira:

  1. Comece pela tabela clientes.
  2. Relacione-a com a tabela pedidos.
  3. Utilize a condição clientes.id = pedidos.cliente_id.
  4. Retorne o nome do cliente e o valor do pedido.

Utilizando aliases

Quando as consultas ficam maiores, podemos utilizar apelidos para as tabelas.

Por exemplo: 

SELECT
    c.nome,
    p.total

FROM clientes AS c

INNER JOIN pedidos AS p
    ON c.id = p.cliente_id;

Agora:

  • c representa clientes.
  • p representa pedidos.

O mesmo pode ser escrito de forma ainda mais curta: 

SELECT
    c.nome,
    p.total

FROM clientes c

JOIN pedidos p
    ON c.id = p.cliente_id;
JOIN sem especificar o tipo

Em muitos SGBDs, escrever apenas JOIN equivale a INNER JOIN.

INNER JOIN e LEFT JOIN

Existem diferentes tipos de JOIN. Dois dos mais importantes para começar são INNER JOIN e LEFT JOIN.

INNER JOIN

Retorna os registros que possuem correspondência nas duas tabelas. 

SELECT
    c.nome,
    p.total

FROM clientes c

INNER JOIN pedidos p
    ON c.id = p.cliente_id;

LEFT JOIN

Retorna todos os registros da tabela que está à esquerda e os dados correspondentes da tabela da direita. 

SELECT
    c.nome,
    p.total

FROM clientes c

LEFT JOIN pedidos p
    ON c.id = p.cliente_id;

Se um cliente não possuir nenhum pedido, o LEFT JOIN ainda pode retornar esse cliente.

Nesse caso, as colunas provenientes de pedidos poderão aparecer como NULL.

Exemplo de LEFT JOIN

Imagine três clientes:

ID Nome
1 Ana
2 João
3 Maria

E somente Ana e João possuem pedidos.

Um INNER JOIN poderá retornar:

Cliente Pedido
Ana 101
João 102

Já um LEFT JOIN poderá retornar:

Cliente Pedido
Ana 101
João 102
Maria NULL

Relacionamento 1:1

No relacionamento um para um (1:1), um registro de uma tabela está relacionado a no máximo um registro de outra tabela.

Um exemplo conceitual seria: 

USUARIO
   │
   │ 1
   │
   ▼
PERFIL

Dependendo das regras do sistema, um usuário pode possuir um único perfil complementar.

Em bancos relacionais, esse tipo de relacionamento pode ser implementado utilizando uma chave estrangeira com uma restrição de unicidade.

Relacionamento N:N

No relacionamento muitos para muitos (N:N), vários registros de uma tabela podem estar relacionados a vários registros de outra.

Um exemplo clássico é:

Um aluno pode participar de várias disciplinas.

Uma disciplina pode possuir vários alunos.

Não costumamos representar esse relacionamento diretamente com uma única chave estrangeira.

Normalmente criamos uma tabela intermediária: 

ALUNOS
   │
   │ 1
   │
   ▼
MATRICULAS
   ▲
   │ 1
   │
   │
DISCIPLINAS

A tabela matriculas poderia possuir: 

CREATE TABLE matriculas (

    aluno_id INT,

    disciplina_id INT,

    PRIMARY KEY (aluno_id, disciplina_id),

    FOREIGN KEY (aluno_id)
        REFERENCES alunos(id),

    FOREIGN KEY (disciplina_id)
        REFERENCES disciplinas(id)

);
Ideia principal:

A tabela intermediária transforma um relacionamento N:N em dois relacionamentos 1:N.

JOIN com WHERE

Podemos combinar JOIN com os recursos aprendidos na Aula 6.

Por exemplo, queremos encontrar pedidos acima de R$ 300: 

SELECT
    c.nome,
    p.id,
    p.total

FROM clientes c

INNER JOIN pedidos p
    ON c.id = p.cliente_id

WHERE p.total > 300;

Também podemos ordenar: 

SELECT
    c.nome,
    p.id,
    p.total

FROM clientes c

INNER JOIN pedidos p
    ON c.id = p.cliente_id

WHERE p.total > 300

ORDER BY p.total DESC;

JOIN com três tabelas

Uma consulta também pode relacionar mais de duas tabelas.

Imagine: 

clientes
    │
    ▼
pedidos
    │
    ▼
itens_pedido
    │
    ▼
produtos

Podemos consultar informações passando por várias relações: 

SELECT
    c.nome,
    p.id,
    pr.nome,
    ip.quantidade

FROM clientes c

INNER JOIN pedidos p
    ON c.id = p.cliente_id

INNER JOIN itens_pedido ip
    ON p.id = ip.pedido_id

INNER JOIN produtos pr
    ON pr.id = ip.produto_id;
Não se assuste!

Consultas com vários JOINs podem parecer complexas inicialmente. O importante é entender cada relacionamento individualmente.

PK × FK

PK FK
Primary Key Foreign Key
Identifica um registro. Referencia um registro de outra tabela.
É única dentro da tabela. Pode aparecer várias vezes.
Exemplo: clientes.id Exemplo: pedidos.cliente_id

INNER JOIN × LEFT JOIN

JOIN O que retorna?
INNER JOIN Registros que possuem correspondência nas duas tabelas.
LEFT JOIN Todos os registros da tabela da esquerda e os correspondentes da direita.

Uma forma simples de memorizar:

INNER JOIN → somente correspondências.

LEFT JOIN → tudo da esquerda + correspondências.

🧠 Mapa mental da aula

🔑 PK → identifica um registro.

🔗 FK → referencia outra tabela.

1:1 → um para um.

1:N → um para muitos.

N:N → muitos para muitos.

🔎 JOIN → combina dados relacionados.

INNER JOIN → somente correspondências.

LEFT JOIN → todos da esquerda + correspondências.

Resumindo

Uma chave primária identifica exclusivamente um registro.

Uma chave estrangeira permite representar um relacionamento entre tabelas.

O relacionamento 1:N é muito comum em bancos relacionais.

Relacionamentos N:N normalmente utilizam uma tabela intermediária.

JOIN permite consultar dados de tabelas relacionadas.

INNER JOIN retorna somente registros correspondentes.

LEFT JOIN mantém todos os registros da tabela da esquerda.
